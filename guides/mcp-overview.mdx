Fused turns every SDK it generates into a fully functional [Model Context Protocol (MCP)](https://modelcontextprotocol.io) server. Your AI agents connect to that server and immediately gain structured, credential-safe access to your integrations — no prompt engineering around raw REST calls, no credentials leaking into context windows.

## What is a Fused MCP server?

A Fused MCP server is an MCP-compliant server compiled directly from your generated SDK. It exposes two purpose-built tools that any MCP-compatible agent or client can call:

<CardGroup cols={2}>
  <Card title="search_docs" icon="magnifying-glass">
    Performs semantic search over the SDK's documentation and method signatures. Pass a natural-language query and receive the exact TypeScript signatures, parameters, and types the agent needs to construct a valid call.
  </Card>
  <Card title="execute_tool" icon="play">
    Accepts a snippet of TypeScript code that uses the SDK, runs it inside a secure sandboxed VM, and returns the output. The agent never touches your infrastructure directly.
  </Card>
</CardGroup>

## Why it matters

Traditional API integrations require agents to guess endpoint paths, craft raw HTTP requests, and handle credentials in plain text. A Fused MCP server eliminates all of that:

- **Typed discovery** — `search_docs` returns exact method signatures so agents always call the right function with the right arguments.
- **Secure execution** — `execute_tool` runs code in an isolated VM. Agents interact with your APIs without ever seeing your credentials.
- **Zero prompt engineering** — agents follow a consistent two-step pattern that works across every integration Fused supports.

## How agents use the two tools

Every agent workflow follows the same pattern: discover first, execute second.

<Steps>
  <Step title="Discover the right method">
    The agent calls `search_docs` with a plain-language description of what it wants to do. Fused returns the matching TypeScript method signatures, parameter names, and types from the SDK.

    ```text
    search_docs("create a Jira ticket")
    → sdk.jira.issues.create({ project, summary, issueType, assignee })
    ```
  </Step>
  <Step title="Execute the workflow">
    Armed with the correct signature, the agent calls `execute_tool` with TypeScript code that uses the SDK. The code runs in a sandboxed VM and the result is returned directly to the agent.

    ```typescript
    const ticket = await sdk.jira.issues.create({
      project: "ONBOARD",
      summary: "Onboard Jane",
      issueType: "Task",
    })
    console.log(ticket.data.key)
    // → "ONBOARD-42"
    ```
  </Step>
</Steps>

## Authentication

Credentials are never embedded in the MCP server itself. You supply them through your MCP client's configuration (for example, as environment variables or a secrets block in your client config). The server receives credentials at runtime from the client — agents only see the return values of API calls, not the keys used to make them.

<Note>
  Fused MCP servers are credential-safe by design. Agents that call `execute_tool` cannot read the environment variables or secrets your MCP client injects — they only receive the structured output of the SDK method.
</Note>

## Deployment options

Choose the deployment model that fits your requirements:

| | Fused-Run (cloud) | Self-hosted |
|---|---|---|
| **Setup** | Zero infrastructure | You manage the runtime |
| **Languages** | TypeScript only | TypeScript and Python |
| **URL** | Hosted SSE URL, ready immediately | Your own endpoint |
| **Data residency** | Fused cloud | Your infrastructure |
| **Best for** | Fast iteration, SaaS integrations | Private networks, compliance, Python |
