The Fused dashboard is your central control plane for everything you build with Fused. From here you ingest upstream API specs, trigger generation of SDKs and MCP servers, monitor for API drift, and download the artefacts your teams depend on. Open the dashboard at [usefused.com/login](https://usefused.com/login).

## Main sections

The left-hand navigation organises the dashboard into five top-level sections:

| Section | What you do here |
|---|---|
| **Services** | Ingest, view, and manage upstream API definitions |
| **SDKs** | Browse, regenerate, and download generated SDK packages |
| **MCP Servers** | Deploy and configure Model Context Protocol servers |
| **Webhooks** | Manage webhook event subscriptions and payloads |
| **API Keys** | Create, rotate, and revoke your Fused API keys |

## Navigating between artefact types

Each service you ingest can produce multiple artefact types — an SDK, an MCP server, and webhook bindings. To move between them:

1. Open **Services** and click the service you want to work with.
2. Use the **Artefacts** tabs at the top of the service detail page to switch between **SDK**, **MCP Server**, and **Webhooks**.
3. Each tab shows the current generation status, the version history, and action buttons.

## Quick actions

<Steps>
  <Step title="Ingest a new service">
    Click **Services → New Service** in the sidebar. Paste your OpenAPI or AsyncAPI spec URL, or upload a file directly. Fused validates the spec and creates a service record you can generate artefacts from.
  </Step>
  <Step title="Generate an SDK">
    Open the service, go to the **SDK** tab, and click **Generate**. Fused compiles a typed SDK from the current spec version. Generation typically completes in a few seconds.
  </Step>
  <Step title="Deploy an MCP server">
    Open the service, go to the **MCP Server** tab, and click **Deploy**. You can configure the server name and target environment before confirming. Once deployed, the endpoint URL appears in the tab.
  </Step>
</Steps>

## How artefacts are listed and versioned

Fused keeps a full version history for every artefact it generates. Inside each artefact tab you will find:

- **Current version** — the latest generated artefact, ready to download or deploy.
- **Version history** — an ordered list of all previous generations, each labelled with a timestamp and the spec version it was generated from.
- **Status badge** — indicates whether the artefact is `Up to date`, `Drift detected`, or `Generation failed`.

Versions are immutable. Generating a new artefact creates a new version entry rather than overwriting the previous one, so you can always roll back.

<Note>
  Version numbers are assigned by Fused and reflect the order of generation, not the version number in your upstream API spec.
</Note>

## Downloading generated artefacts

To download any artefact:

1. Navigate to the relevant artefact tab (e.g. **SDK**).
2. Locate the version you want in the version list.
3. Click the **Download** button next to that version.

Artefacts are delivered as compressed archives (`.zip` or `.tar.gz` depending on type). You can also pull artefacts programmatically using the CLI — see the [CLI overview](/cli/overview).

<Tip>
  Pin a specific version in your CI pipeline by copying the permalink shown next to each version entry. This ensures your builds use a known-good artefact until you explicitly upgrade.
</Tip>

## Settings and notifications

The **Settings** section (bottom of the left sidebar) is where you configure account-level preferences:

- **API Keys** — generate or revoke keys used by the CLI and SDK.
- **Notifications** — configure email alerts for drift events and generation failures.
- **Team** — invite collaborators and manage their access levels.
