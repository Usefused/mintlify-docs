title: "Self-Host a Fused MCP Server in Your Infrastructure"
sidebarTitle: "Self-Host"

---

Self-hosting gives you complete ownership of your MCP server. The generated source code runs in any Node.js or Python environment you control — on-premises, in a private VPC, or on your own cloud account. No Fused runtime is involved after you download the code, and no telemetry is sent back to Fused.

## When to self-host

<CardGroup cols={2}>
  <Card title="Data sovereignty" icon="shield-halved">
    Keep all API traffic and credentials inside your own network perimeter. Nothing transits Fused infrastructure after the initial code download.
  </Card>
  <Card title="Python MCP servers" icon="python">
    Fused-Run only supports TypeScript. If your workflow requires a Python server, self-hosting is the supported path.
  </Card>
  <Card title="Private networks" icon="lock">
    Connect agents to internal APIs that are not reachable from the public internet, such as on-prem databases or intranet services.
  </Card>
  <Card title="Custom runtimes" icon="gears">
    Run the server alongside other services in your existing container orchestration setup, with whatever resource limits and monitoring you prefer.
  </Card>
</CardGroup>

## Step 1 — Generate and download the MCP server

You can generate and download the server source from the dashboard or from the CLI.

<Tabs>
  <Tab title="CLI (recommended)">
    <Steps>
      <Step title="Generate the MCP server">
        Use `fused-cli create` with `-t mcp`. Omit `--deploy` to keep the output local. Pass `-l python` for a Python server or omit it for TypeScript (the default).

        <CodeGroup>
          ```bash TypeScript
          fused-cli create --name support-agent-mcp -t mcp \
            -d "Answer support tickets using Zendesk and Notion"
          ```

          ```bash Python
          fused-cli create --name support-agent-mcp -t mcp -l python \
            -d "Answer support tickets using Zendesk and Notion" -y
          ```
        </CodeGroup>

        The `-y` flag skips interactive confirmation prompts.
      </Step>
      <Step title="Download the source archive">
        ```bash
        fused-cli download support-agent-mcp
        ```

        This saves `support-agent-mcp.zip` to your current directory.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Dashboard">
    <Steps>
      <Step title="Open your SDK in the Fused dashboard">
        Navigate to **SDKs** in the [Fused dashboard](https://app.usefused.com) and open the SDK you want to expose as an MCP server.
      </Step>
      <Step title="Generate an MCP server">
        Click **Generate** → **MCP Server**. Select your language (TypeScript or Python) and click **Create**.
      </Step>
      <Step title="Download the .zip">
        Once generation completes, click **Download source** to save the `.zip` archive to your machine.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Step 2 — Run the server

Extract the `.zip` and follow the steps for your language.

<CodeGroup>
  ```bash TypeScript
  unzip support-agent-mcp.zip -d support-agent-mcp
  cd support-agent-mcp
  npm install
  npm start
  ```

  ```bash Python
  unzip support-agent-mcp.zip -d support-agent-mcp
  cd support-agent-mcp
  pip install -e .
  python -m support_agent_mcp
  ```
</CodeGroup>

<Steps>
  <Step title="Extract the archive">
    ```bash
    unzip support-agent-mcp.zip -d support-agent-mcp
    cd support-agent-mcp
    ```
  </Step>
  <Step title="Install dependencies">
    <CodeGroup>
      ```bash TypeScript
      npm install
      ```

      ```bash Python
      pip install -e .
      ```
    </CodeGroup>
  </Step>
  <Step title="Set your credentials as environment variables">
    The server reads credentials from environment variables at startup. Check the generated `README.md` in the archive for the full list of variables your specific integrations require.

    <CodeGroup>
      ```bash TypeScript
      export ZENDESK_API_TOKEN=your-token
      export NOTION_API_KEY=your-key
      npm start
      ```

      ```bash Python
      export ZENDESK_API_TOKEN=your-token
      export NOTION_API_KEY=your-key
      python -m support_agent_mcp
      ```
    </CodeGroup>
  </Step>
  <Step title="Note the server address">
    The server prints its listening address when it starts:

    ```text
    Fused MCP server listening on http://localhost:3000/sse
    ```

    For Python servers using stdio transport, no port is printed — see the connection section below.
  </Step>
</Steps>

## Step 3 — Connect your MCP client

How you connect depends on whether your server uses HTTP (SSE) or stdio transport. Both are supported by the generated server; the generated `README.md` specifies which transport your server uses by default.

<Tabs>
  <Tab title="HTTP / SSE transport">
    Point your MCP client at the local SSE URL:

    <CodeGroup>
      ```json Claude Desktop
      {
        "mcpServers": {
          "support-agent-mcp": {
            "url": "http://localhost:3000/sse"
          }
        }
      }
      ```

      ```json Cursor
      {
        "servers": {
          "support-agent-mcp": {
            "url": "http://localhost:3000/sse"
          }
        }
      }
      ```
    </CodeGroup>
  </Tab>
  <Tab title="stdio transport">
    For stdio transport, configure your client to launch the server process directly:

    <CodeGroup>
      ```json Claude Desktop (TypeScript)
      {
        "mcpServers": {
          "support-agent-mcp": {
            "command": "node",
            "args": ["/path/to/support-agent-mcp/dist/index.js"],
            "env": {
              "ZENDESK_API_TOKEN": "your-token",
              "NOTION_API_KEY": "your-key"
            }
          }
        }
      }
      ```

      ```json Claude Desktop (Python)
      {
        "mcpServers": {
          "support-agent-mcp": {
            "command": "python",
            "args": ["-m", "support_agent_mcp"],
            "env": {
              "ZENDESK_API_TOKEN": "your-token",
              "NOTION_API_KEY": "your-key"
            }
          }
        }
      }
      ```
    </CodeGroup>

    <Tip>
      Use stdio transport when your server and MCP client run on the same machine. It avoids opening a network port and is the simplest setup for local development.
    </Tip>
  </Tab>
</Tabs>

## What you own

<Note>
  Self-hosted servers are fully yours. Once you download the source:
  - No vendor runtime is required to keep the server running.
  - No telemetry or usage data is sent back to Fused.
  - You can modify the source code, add middleware, or integrate it into your existing deployment pipeline.
</Note>

The generated code is standard TypeScript (Node.js) or Python. Treat it like any other service you maintain: add it to version control, containerize it, and deploy it alongside your other infrastructure.
