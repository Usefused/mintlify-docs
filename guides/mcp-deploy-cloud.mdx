Fused-Run is the fastest way to get an MCP server in front of your agents. Run one CLI command and Fused provisions a hosted server, wires up your SDK, and hands you a live SSE URL — no Docker images, no cloud consoles, no infrastructure to maintain.

## Prerequisites

Before you deploy, make sure you have the following ready:

- A TypeScript SDK already generated in Fused (see [SDK Overview](/guides/sdk-overview))
- `fused-cli` installed (`npm install -g fused-cli`)
- Your `FUSED_API_KEY` exported in your shell:

```bash
export FUSED_API_KEY=fused_sk_...
```

<Warning>
  Fused-Run only supports TypeScript MCP servers. If your workflow requires Python, see [Self-Host a Fused MCP Server](/guides/mcp-self-host) instead.
</Warning>

## Deploy your MCP server

<Steps>
  <Step title="Run fused-cli create with the --deploy flag">
    Pass `--deploy` alongside `-t mcp` to generate the server **and** push it to Fused-Run in a single command. The `-d` flag gives Fused the context it needs to generate accurate method bindings.

    ```bash
    fused-cli create --name sales-mcp -t mcp --deploy \
      -d "Read Salesforce leads and fetch Intercom conversations"
    ```

    Fused compiles your SDK into an MCP server, uploads it to Fused-Run, and boots the process.
  </Step>
  <Step title="Copy your SSE URL">
    Once the deploy finishes, the CLI prints your server's dedicated SSE endpoint:

    ```text
    ✓ Deployed sales-mcp to Fused-Run
      SSE URL: https://run.usefused.com/mcp/sales-mcp/sse
    ```

    Each deployment gets its own URL. Copy it — you'll paste it into your MCP client next.
  </Step>
  <Step title="Connect your MCP client">
    Open your MCP client's configuration and add the SSE URL as a new server. The exact format depends on your client:

    <CodeGroup>
      ```json Claude Desktop (claude_desktop_config.json)
      {
        "mcpServers": {
          "sales-mcp": {
            "url": "https://run.usefused.com/mcp/sales-mcp/sse",
            "env": {
              "SALESFORCE_ACCESS_TOKEN": "your-token",
              "INTERCOM_API_KEY": "your-key"
            }
          }
        }
      }
      ```

      ```json Cursor (mcp.json)
      {
        "servers": {
          "sales-mcp": {
            "url": "https://run.usefused.com/mcp/sales-mcp/sse",
            "env": {
              "SALESFORCE_ACCESS_TOKEN": "your-token",
              "INTERCOM_API_KEY": "your-key"
            }
          }
        }
      }
      ```
    </CodeGroup>

    <Tip>
      The `env` block in your client config is how credentials reach your MCP server at runtime. Agents never see these values directly — they only receive the output of SDK calls.
    </Tip>
  </Step>
  <Step title="Test the connection">
    Ask your agent a question that exercises the integration. A healthy server responds to `search_docs` within a few hundred milliseconds:

    ```text
    search_docs("list open Salesforce leads")
    → sdk.salesforce.leads.list({ status: "Open", limit, offset })
    ```

    If the agent returns a method signature, your server is live and ready.
  </Step>
</Steps>

## Update a deployed server

When your underlying SDK changes, redeploy the MCP server with the `update` command:

```bash
fused-cli update sales-mcp --deploy
```

Fused rebuilds the server from your latest SDK and replaces the running instance. The SSE URL stays the same — your clients reconnect automatically.

## Manage servers from the dashboard

Every deployed server appears in the **MCP Servers** section of the [Fused dashboard](https://app.usefused.com). From there you can:

- View live server status and uptime
- Rotate or revoke the SSE URL
- Review recent `execute_tool` invocations and their outputs
- Delete a deployment

## Limitations

<Info>
  - **TypeScript only.** Fused-Run does not currently support Python MCP servers. Use `fused-cli create -l python` with self-hosting instead.
  - **One URL per deployment.** Each named server gets its own dedicated SSE endpoint. Deploying the same name again replaces the existing server.
  - **Runtime environment.** Fused-Run executes `execute_tool` code in an isolated Node.js VM. Code that requires native binaries or filesystem access is not supported.
</Info>
