The Fused Service Library is a curated collection of pre-configured services for the most popular third-party APIs. Instead of ingesting a spec yourself, you pick a service from the library and add it to your account in one click. Every library service comes pre-configured with the correct authentication schemes, logical endpoint groupings, and webhook definitions — so you can start generating SDKs, MCP servers, and webhook receivers immediately, without hunting down a spec file or untangling auth flows.

## How library services differ from custom services

Both library services and custom services are full Fused service definitions — they power the same artefacts in the same way. The difference is in how they're created and maintained:

| | Library service | Custom service |
|---|---|---|
| **Created by** | Fused team | You |
| **Auth pre-configured** | ✅ Yes | You configure during ingestion |
| **Endpoint groupings** | Curated by Fused | Based on spec tags or paths |
| **Webhook definitions** | Pre-configured where available | Extracted from spec, or added manually |
| **Updates** | Maintained by Fused team | You re-ingest to pick up changes |
| **Scope customisation** | ✅ You can still deselect endpoints | ✅ Full control |

<Note>
  Library services are kept up to date by the Fused team. When an upstream API releases a new version or changes its auth scheme, Fused updates the library service and notifies you so you can regenerate affected artefacts. Custom services require you to manually re-ingest the spec or configure drift alerts.
</Note>

## Add a library service to your account

<Steps>
  <Step title="Open the Service Library">
    In the Fused dashboard, click **Services** in the sidebar, then click **Browse library** (or the **Library** tab at the top of the Services page).
  </Step>
  <Step title="Find the service you need">
    Use the search bar to find a service by name or category (e.g. "CRM", "ticketing", "version control"). Each service card shows the API name, a brief description, and the authentication method it uses.
  </Step>
  <Step title="Preview the service">
    Click a service card to open the detail view. Here you can see every endpoint group included in the service, the authentication scheme, and which webhook events are pre-configured. This is a read-only preview — you haven't added anything to your account yet.
  </Step>
  <Step title="Add the service">
    Click **Add to my services**. Fused copies the library service into your account as a fully editable instance. Your copy is independent — changes to the library service (e.g. a Fused-team update) are surfaced as available upgrades, not applied automatically.
  </Step>
  <Step title="Scope your endpoints">
    After adding the service, you can deselect any endpoints you don't need. Click **Edit service**, uncheck the operations you want to exclude, and save. This affects only your copy — the library definition is unchanged.
  </Step>
  <Step title="Generate artefacts">
    Your service is ready. Navigate to **SDKs**, **MCP servers**, or **Webhooks** to generate artefacts from it.
  </Step>
</Steps>

<Tip>
  Even for APIs in the library, you can create a custom service instead if you need full control over ingestion — for example, if you're using a self-hosted instance of Jira or a private GitHub Enterprise deployment with a non-standard spec.
</Tip>

## Staying up to date with library services

When the Fused team updates a library service (for example, after a major API version change), you receive a notification in the dashboard. You can:

- **Review the diff** — see exactly which endpoints were added, modified, or removed.
- **Accept the update** — apply the changes to your copy of the service.
- **Defer the update** — keep your current version and revisit the update later.

Accepting an update does not automatically regenerate your artefacts. You trigger regeneration separately so you can test and validate before shipping changes to consumers.

<Warning>
  If you defer a library update for an extended period, your artefacts may fall behind the upstream API, which can cause runtime errors. Fused shows a badge on out-of-date services in your dashboard.
</Warning>

## Requesting a new service

Don't see the API you need? Submit a library request:

1. Go to **Services → Browse library**.
2. Click **Request a service** at the bottom of the page.
3. Enter the API name, a link to its documentation or OpenAPI spec, and a brief note about your use case.

The Fused team reviews requests and prioritises based on demand. You can track the status of your request from the **Requests** tab in the library.

<Info>
  If you need a service immediately and can't wait for a library addition, create a custom service using the [OpenAPI ingestion](/guides/ingest-openapi) or [GraphQL ingestion](/guides/ingest-graphql) flow. You can replace it with the library version later with no changes to your artefacts.
</Info>
