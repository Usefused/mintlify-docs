A service is the core building block in Fused. When you ingest an API — whether it's a public SaaS product, an internal microservice, or a partner integration — Fused parses the spec and stores the result as a service: a structured, reusable definition that captures everything needed to generate typed artefacts. You create a service once and reuse it across every SDK, MCP server, and webhook receiver you build.

## What Fused extracts from your API

When you provide Fused with an API specification, it extracts four categories of information:

- **Endpoints** — every path and HTTP operation (GET, POST, PUT, PATCH, DELETE), including request parameters, request bodies, and response schemas.
- **Authentication methods** — API keys, Bearer tokens, OAuth 2.0 flows, and any other security schemes declared in the spec.
- **Webhook configuration** — outbound event definitions and payload schemas, where present in the spec.
- **Operational settings** — base URLs, server variables, rate-limit hints, and any extension metadata declared in the spec.

Fused normalises all of this into a single service definition regardless of the original spec format.

## How services power artefacts

A service sits upstream of every artefact you generate. One service can power:

- **Typed SDKs** — Fused generates a fully typed client library in your target language, using the endpoints and schemas from the service.
- **MCP servers** — Fused exposes the service's operations as an MCP-compatible server, ready for AI agents and tooling.
- **Webhook receivers** — Fused scaffolds typed receiver functions from the service's webhook definitions, so you handle inbound events with full type safety.

Because the service is the single source of truth, updating a service (for example, after an API version bump) propagates to every artefact derived from it.

## Service library vs custom services

Fused provides two ways to get a service:

**Service library** — A growing collection of pre-curated services for popular third-party APIs such as GitHub, Jira, Slack, Salesforce, Zendesk, Linear, and Intercom. Library services are maintained by the Fused team and come pre-configured with correct auth schemes, endpoint groupings, and webhook definitions. You can add a library service to your account in one click and immediately start generating artefacts.

**Custom services** — You create these yourself by ingesting a spec from any supported format. Custom services are ideal for internal APIs, private partner APIs, or any third-party API not yet in the library. You own the ingestion lifecycle and can re-ingest the spec at any time to pick up changes.

<Note>
  Internal, partner, and third-party APIs are all supported as custom services. If your API is internal, paste the spec directly into the dashboard or make sure the spec URL is reachable from Fused's ingestion service.
</Note>

## How to create a service

<Steps>
  <Step title="Open the Services dashboard">
    Navigate to **Services** in the Fused dashboard sidebar and click **New service**.
  </Step>
  <Step title="Choose an ingestion format">
    Select the format that matches your API: **OpenAPI**, **GraphQL**, **Postman Collection**, or **Docs URL**. Each format has its own ingestion flow — see the guides linked below for details.
  </Step>
  <Step title="Provide your spec">
    Paste a URL pointing to the spec, upload a file, or paste raw JSON or YAML directly into the editor. Fused fetches and parses the spec immediately.
  </Step>
  <Step title="Review extracted endpoints">
    Fused displays every endpoint it found. Review the list, deselect any operations you don't need, and confirm your selection. You can change this later without re-ingesting the spec.
  </Step>
  <Step title="Configure authentication">
    Fused pre-fills the authentication method from the spec. Confirm the scheme (API key, Bearer, OAuth 2.0) and enter the credential placeholders your consumers will supply at runtime.
  </Step>
  <Step title="Save and name the service">
    Give the service a descriptive name, then click **Save**. The service appears in your Services dashboard and is immediately available for artefact generation.
  </Step>
</Steps>

<Tip>
  You can re-ingest a spec at any time to pick up new endpoints or schema changes. Fused shows you a diff of what changed so you can decide which updates to accept before regenerating artefacts.
</Tip>
