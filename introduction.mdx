Fused connects your applications and AI agents to internal and external APIs through one controlled runtime. It handles provider credentials, access control, retries, pagination, and execution records so you can focus on what your software does.

Create one **App** to deliver its selected operations as a typed SDK, an Engine REST API, and a hosted MCP server. The three methods share one App identity, immutable version, and execution token. Fused keeps provider credentials out of your application code and agent context.

## How it works

<CardGroup cols={2}>
  <Card title="Registry" icon="cloud">
    A catalogue of versioned service contracts that describe APIs and how to connect to them.
  </Card>
  <Card title="Engine" icon="server">
    Your workspace runtime, hosted or self-hosted. It checks access, resolves credentials, calls providers, and records each execution.
  </Card>
</CardGroup>

Your [workspace](/workspace/enable-a-service) defines which services are available. Each App exposes the operations its callers need, and [buckets](/bucket/store-credentials) hold the provider credentials used for those calls.

## Get started

First, [get an Engine running](/deploy-an-engine). Then create an App with all three delivery methods, or choose one method explicitly:

<CardGroup cols={2}>
  <Card title="Create your first App" icon="cube" href="/quickstart">
    Install the CLI, select operations once, and use the SDK, MCP, or REST method.
  </Card>
  <Card title="Deploy an MCP server" icon="robot" href="/mcp/deploy-a-server">
    Give an agent scoped access to operations across your services.
  </Card>
</CardGroup>

Need only one method? Follow the [SDK-only](/app/build-an-sdk) or [MCP-only](/mcp/deploy-a-server) guide. For HTTP without a generated package, use the [REST-only setup](/app/build-an-sdk#skip-the-package).
