**Fused - Connect Your APIs Once, Use Everywhere**

In a team workspace, approve internal and partner APIs so developers can build with a typed SDK, deploy a shared Unified App template with their own credential bucket, or give an agent selected tools through MCP.

For a solo project or business, start a lightweight workspace in Fused Cloud or host it yourself. Use separate buckets for project secrets and choose which services each assistant can access.

Create one **App** to deliver its selected operations as a typed SDK, a Fused REST API, and a hosted MCP server. The three methods share one App identity, immutable version, and execution token. Fused keeps provider credentials out of your application code and agent context.

## How it works

<CardGroup cols={2}>
  <Card title="Registry" icon="cloud">
    A catalogue of versioned service contracts that describe APIs and how to connect to them.
  </Card>
  <Card title="Fused Engine" icon="server">
    Your workspace runtime, hosted or self-hosted. It checks access, resolves credentials, calls providers, and records each execution.
  </Card>
</CardGroup>

Your [workspace](/workspace/enable-a-service) defines which services are available. Each App exposes the operations its callers need, and [buckets](/bucket/store-credentials) hold the provider credentials used for those calls.

## Get started

First, [get Fused running](/deploy-an-engine). Then create an App with all three delivery methods, or choose one method explicitly:

<CardGroup cols={2}>
  <Card title="Create your first App" icon="cube" href="/quickstart">

  </Card>
  <Card title="Deploy an MCP server" icon="robot" href="/mcp/deploy-a-server">
    Give an agent scoped access to operations across your services.
  </Card>
