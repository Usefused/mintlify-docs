## ChannelAdapter

Platform-specific transport that normalizes events and sends replies.

Extensions implement this contract without exposing raw provider drivers.
Normalization is synchronous and offline so fixtures can be tested without
live credentials; sending is the only network-owned operation.

## ChannelBinding

Local policy connecting one platform conversation scope to this agent.

`extension` names the registered ChannelAdapter factory that owns the
platform transport (for example a Fused-backed Slack extension, or a
direct-API extension); the binding itself never depends on how that
extension talks to the platform. Empty allow-lists mean nothing is
authorized yet, not that everything is; an adapter must fail closed.

```python
ChannelBinding(
    platform: str,
    extension: str,
    allowed_installations: tuple[str, ...] = (),
    allowed_conversations: tuple[str, ...] = (),
    config: Mapping[str, Any] = ...,
) -> None
```

## ChannelEvent

One inbound platform message, normalized by a ChannelAdapter.

`delivery_id` identifies this specific transport delivery and may repeat
across retries; `provider_event_id` is the platform's stable identity for
deduplication. `reply_to` is an opaque, adapter-owned address a later
reply must target and is never interpreted by the store.

```python

    platform: str,
    installation_id: str,
    provider_event_id: str,
    kind: str,
    sender_id: str,
    conversation_id: str,
```

## ChannelReply

One outbound answer queued for durable, at-least-once delivery.

`status` is pending, sent, failed, or delivery_unknown (an ambiguous
send that must be reconciled before replay, never blindly retried).

## ChannelStore

Atomic operations required for durable, deduplicated channel messaging.

All identity, scope, and ordering predicates execute inside the datastore.
A provider must durably commit before returning success.

```python

```

### ChannelStore.start

```python

```

Open owned resources and initialize the provider's durable schema.

### ChannelStore.close

```python

```

### ChannelStore.admit_event

```python
async ChannelStore.admit_event(event: ChannelEvent) -> tuple[ChannelEvent, bool]
```

Atomically persist a new event or return an identical prior admission.

Deduplication is scoped by platform, installation, and provider event
ID. A conflicting definition under the same identity raises
ChannelStoreConflictError. The second return value is True only for a
newly admitted event.

## ChannelWorker

Admit before ACK, fence work, and persist replies before any provider send.

The caller owns the started task store and authenticated invoke/send callbacks.
Jobs never automatically retry an ambiguous model execution or provider send.
Pending jobs survive restart; interrupted claimed jobs require reconciliation.

```python
ChannelWorker(
    *,
    application_id: str,
    binding_id: str,
    binding: ChannelBinding,
    store: TaskStore,
    invoke: Any,
    send: Any,
    allowed_senders: tuple[str, ...],
    allowed_kinds: tuple[str, ...] = ('app_mention',),
    timeout: float = 120,
    not_before: float = 0,
) -> None
```

### ChannelWorker.accepts

```python
ChannelWorker.accepts(event: ChannelEvent) -> bool
```

Recheck policy at intake and execution, including work retained before changes.

### ChannelWorker.admit

```python
async ChannelWorker.admit(event: ChannelEvent) -> str | None
```

Commit input and dispatch intent in one atomic, idempotent task admission.

### ChannelWorker.step

```python
async ChannelWorker.step() -> int
```

### ChannelWorker.run

```python

```

Drain bounded work until shutdown; the receiver must stop before this worker.

## discover_channel_bindings

Load every ChannelBinding exported by a project's channels/ directory.

per binding, named after the platform, exporting a callable `binding()`.
