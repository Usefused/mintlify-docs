<Steps>
  <Step title="Scaffold the extension">
    Run inside an agent folder, inside a pack folder, or pass `--output DIR` for a standalone location (the name must be a valid Python identifier):

    ```bash
    # Inside an agent or pack directory
    harnest extensions init warehouse --contribute tools,lifecycle --capability lifecycle.tool

    # Standalone directory (no config.yaml required)
    harnest extensions init warehouse --output ./extensions --contribute tools
    ```

    `harnest extensions init` generates `extension.yaml`, `extension.py`, and `pyproject.toml`. `--contribute` also creates each requested folder (`lifecycle`, `tools`, `mcp`, `skills`, `subagents`), wires `contributes:` in `extension.yaml`, and adds matching `content.*` capabilities.

    ```text extensions/warehouse/
    extensions/warehouse/
      extension.yaml     # required: manifest, capabilities, contributed folders
      extension.py       # required: exports `extension` singleton
      pyproject.toml     # generated (optional): third-party SDK dependencies
      README.md          # optional: package docs for PyPI
      lib/               # optional: private helpers (never auto-discovered)
      lifecycle/         # optional: hooks, output policies, storage, routes
      tools/             # optional: managed Agent Tools
      mcp/               # optional: managed MCP clients
      skills/            # optional: managed Agent Skills
      subagents/         # optional: managed SubAgents
    ```
  </Step>

  <Step title="Start minimal: contribute tools or policies">
    If your extension only contributes tools, skills, MCP servers, or lifecycle hooks, `extension.py` only needs a 3-line [`Extension`](/harnest/reference/api/extensions#extension) subclass:

    ```yaml extensions/warehouse/extension.yaml
    apiVersion: harnest.dev/v1alpha1
    kind: Extension
    metadata:
      name: warehouse
      version: 1.0.0
    capabilities:
      - content.tools
    contributes:
      tools:
        - tools
    ```

    ```python extensions/warehouse/extension.py
    from harnest.extensions import Extension

    class WarehouseExtension(Extension):
        """Contributes warehouse tools."""

    extension = WarehouseExtension()
    ```

    ```python extensions/warehouse/tools/ping.py
    from harnest.agent import tool

    @tool
    def ping_warehouse() -> str:
        """Check warehouse connectivity."""
        return "ok"
    ```

    `contributes` is explicit—Harnest never infers contributions from folder names alone. Put private helper modules inside `lib/` and import them with relative imports (`from .lib.helpers import ...` in `extension.py`, or `from ..lib.helpers import ...` in `lifecycle/`, `tools/`, `mcp/`, and `subagents/`) so they stay isolated from the agent's own `lib/`. See [Manifest (`extension.yaml`)](/harnest/build/extensions/manifest) for every field and capability.
  </Step>

  <Step title="Add SDK startup and typed request context (optional)">
    When wrapping a long-lived SDK client (database pool, HTTP client), open it in [`start()`](/harnest/reference/api/extensions#extension-start), close it in [`stop()`](/harnest/reference/api/extensions#extension-stop), and expose per-request methods via [`ExtensionContext`](/harnest/reference/api/extensions#extensioncontext):

    ```python extensions/warehouse/extension.py
    import os
    from harnest.extensions import Extension, ExtensionContext
    from warehouse_sdk import WarehouseClient

    class WarehouseContext(ExtensionContext):
        """Per-request view revoked automatically when the invocation ends."""
        __slots__ = ("_owner",)

        def __init__(self, extension_name: str, owner: "Warehouse") -> None:
            super().__init__(extension_name)
            self._owner = owner

        async def query(self, statement: str) -> list[dict]:
            self._require_active()
            return await self._owner._query(statement)

    class Warehouse(Extension[WarehouseContext]):
        """Owns one WarehouseClient for the application lifetime."""
        def __init__(self) -> None:
            self._client = None

        async def start(self, _context) -> None:
            self._client = await WarehouseClient.connect(
                endpoint=os.environ["WAREHOUSE_ENDPOINT"],
            )

        async def stop(self) -> None:
            if self._client is not None:
                await self._client.close()
                self._client = None

        def create_context(self, base: ExtensionContext) -> WarehouseContext:
            return WarehouseContext(base.extension_name, self)

        async def query(self, statement: str) -> list[dict]:
            # Routes through the active request's WarehouseContext
            return await self.context.query(statement)

        async def _query(self, statement: str) -> list[dict]:
            if self._client is None:
                raise RuntimeError("Warehouse extension is not started")
            return await self._client.query(statement)

    extension = Warehouse()
    ```

    Keep raw SDK clients private on `self` and expose only safe domain methods on `WarehouseContext`.
  </Step>

  <Step title="Declare SDK dependencies (pyproject.toml)">
    `harnest extensions init` creates `pyproject.toml` for you. Add any third-party Python packages your extension imports under `[project].dependencies`:

    ```toml extensions/warehouse/pyproject.toml
    [project]
    name = "harnest-extension-warehouse"
    version = "0.1.0"
    requires-python = ">=3.11"
    dependencies = [
      "warehouse-sdk>=2,<3",
    ]

    [tool.uv]
    package = false
    ```

    | Requirement | Rule |
    |---|---|
    | `name` | Must equal `harnest-extension-<metadata.name>` with underscores converted to hyphens (for example `company_adk` → `harnest-extension-company-adk`). |
    | `version` | Must match `metadata.version` in `extension.yaml`. |
    | `dependencies` | Static PEP 621 list only (`dynamic = ["dependencies"]` is rejected). Merged into the agent's root `harnest-runtime.lock` (extensions never get a separate runtime venv). |
    | Forbidden packages | Never declare compiler-owned packages: `harnest`, `google-adk`, `langgraph`, `langchain`, `langchain-litellm`, or `langchain-mcp-adapters`. |
    | `[tool.uv] package = false` | Keeps local and pack extensions as dependency manifests (omit and add `[build-system]` only when publishing to PyPI). |
    | Optionality & limits | Optional when the extension has no extra dependencies; when present, must be a regular file (no symlink) under 1 MiB with a `[project]` table. |
  </Step>

  <Step title="Sync editor packages and test">
    Run `harnest env sync` in an agent, pack, or standalone extension folder to create a managed environment (`.harnest/`), link `.venv`, and point `.vscode/settings.json` at the interpreter so your editor resolves `harnest`, framework SDKs (`google.adk`, `langgraph`), and `pyproject.toml` dependencies:

    ```bash
    # Inside an agent, pack, or standalone extension folder
    harnest env sync .

    # Optional in pack or standalone extension folders: narrow to one framework
    harnest env sync . --framework adk

    # Inside an agent folder
    harnest test .
    ```
  </Step>
</Steps>

## Share across multiple agents

- **Via a company Pack (recommended for internal orgs):** List the extension folder under `extensions:` in `pack.yaml` so your branded CLI auto-loads it into every compiled agent. See [Policies, plugins & bundles](/harnest/build/project-packs/capabilities#enforce-policies-with-pack-owned-extensions).
- **Via PyPI:** Build a universal `py3-none-any` wheel for `harnest-extension-<name>` that registers `[project.entry-points."harnest.extensions"]` (`warehouse = "harnest_extension_warehouse.extension:extension"`) and packages `extension.yaml`, `extension.py`, and optional `README.md`.
