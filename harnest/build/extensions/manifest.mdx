Every Harnest Extension starts with `extension.yaml` (max 1 MiB). Harnest validates it without executing Python code.

## Complete example

```yaml extensions/warehouse/extension.yaml
# Required: fixed schema version and kind.
apiVersion: harnest.dev/v1alpha1
kind: Extension

# Required: name must match the folder (valid Python identifier); version must be SemVer.
metadata:
  name: warehouse
  version: 1.0.0

# Optional: defaults to `extension:extension` when omitted.
runtime:
  entrypoint: extension:extension

# Optional: other local extensions that must start before this one (cycles are rejected).
requires:
  extensions:
    - credentials

# Optional: directories composed into the agent (only declared paths are discovered).
contributes:
  lifecycle: [lifecycle]
  tools: [tools]
  mcp: [mcp]
  skills: [skills]
  subagents: [subagents]

# Optional: explicit permissions required for each hook, resource, or contributed folder.
capabilities:
  - content.tools
  - content.mcp
  - content.skills
  - content.subagents
  - lifecycle.tool
  - policy.output
```

## Field reference

| Field | Required | Rules & meaning |
|---|---|---|
| `apiVersion` | Yes | Literal `harnest.dev/v1alpha1`. |
| `kind` | Yes | Literal `Extension`. |
| `metadata.name` | Yes | Valid Python identifier matching the enclosing folder name (`extensions/<name>/`). |
| `metadata.version` | Yes | SemVer string (for example `1.0.0`); must match `pyproject.toml` version if present. |
| `runtime.entrypoint` | No | Optional; defaults to `extension:extension` (only `extension:extension` is accepted if specified). |
| `requires.extensions` | No | List of extension names that must start before this extension (and stop after it). |
| `contributes` | No | Map of contribution key (`lifecycle`, `tools`, `mcp`, `skills`, `subagents`) to extension-relative folder paths. Paths must exist, cannot overlap, and cannot target reserved roots (`extension.yaml`, `extension.py`, `pyproject.toml`, `README.md`, `lib`). |
| `capabilities` | No | Explicit permissions this extension uses (see below). |

## Contributions reference

Accepted keys for `contributes:` and `harnest extensions init --contribute`:

| Key | Files inside folder | Required capability | Advanced mode |
|---|---|---|---|
| `lifecycle` | `@lifecycle.*` hooks, policies, storage, routes, framework extensions | Matching `lifecycle.*`, `storage.*`, `policy.output`, `http.routes`, `sandbox.provider`, `framework.extension`, or `telemetry.exporter` | Supported |
| `tools` | `@tool` / `@client_tool` modules | `content.tools` | Rejected |
| `mcp` | `client()` MCP modules | `content.mcp` | Rejected |
| `skills` | `<skill>/SKILL.md` folders | `content.skills` | Rejected |
| `subagents` | SubAgent modules | `content.subagents` | Rejected |

## `pyproject.toml` requirements

`harnest extensions init` scaffolds `pyproject.toml` automatically. It is optional if your extension has no third-party dependencies; when present, Harnest validates it against these rules:

| Field / constraint | Requirement |
|---|---|
| File type & size | Regular file (no symlink), max 1 MiB, valid TOML with a PEP 621 `[project]` table. |
| `project.name` | Must equal `harnest-extension-<metadata.name>` with underscores replaced by hyphens. |
| `project.version` | Must match `metadata.version` in `extension.yaml` exactly. |
| `project.dependencies` | Static list of PEP 508 strings (`dynamic = ["dependencies"]` is rejected). |
| Compiler-owned packages | Rejected if listed: `harnest`, `google-adk`, `langgraph`, `langchain`, `langchain-litellm`, `langchain-mcp-adapters`. |
| `[tool.uv] package = false` | Recommended for local and pack-bundled extensions so `uv` treats the file as a dependency manifest rather than a buildable package. |
