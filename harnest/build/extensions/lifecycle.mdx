## Three lifecycle layers

| Layer | Where you write it | Runs when |
|---|---|---|
| Process startup / shutdown | [`Extension.start()`](/harnest/reference/api/extensions#extension-start) and [`Extension.stop()`](/harnest/reference/api/extensions#extension-stop) in `extension.py` | Once per agent process |
| Request context | [`Extension.create_context()`](/harnest/reference/api/extensions#extension-create_context) in `extension.py` | Once per invocation (revoked when the request ends) |
| Hooks, policies & factories | `extensions/<name>/lifecycle/*.py` (listed in `contributes.lifecycle`) | At each decorated lifecycle phase |

## Startup and shutdown order

```text
Startup:   Storage factories  ──▶  Extension.start() (requires order)  ──▶  @lifecycle.resource
Shutdown:  @lifecycle.resource ──▶ Extension.stop()  (reverse order)   ──▶  Storage factories
```

Because `Extension.start()` runs before `@lifecycle.resource`, [`ExtensionStartContext`](/harnest/reference/api/extensions#extensionstartcontext) exposes live custom storage ([`storage`](/harnest/reference/api/extensions#extensionstartcontext-storage)) and declared continuations ([`continuations`](/harnest/reference/api/extensions#extensionstartcontext-continuations))—not arbitrary resources or per-request credentials.

## Contribute a lifecycle hook

List the folder under `contributes.lifecycle` **and** declare the matching capability in `extension.yaml`:

```yaml extensions/warehouse/extension.yaml
apiVersion: harnest.dev/v1alpha1
kind: Extension
metadata:
  name: warehouse
  version: 1.0.0
runtime:
  entrypoint: extension:extension
contributes:
  lifecycle: [lifecycle]
capabilities:
  - lifecycle.tool
```

```python extensions/warehouse/lifecycle/tool_policy.py
from harnest import lifecycle

@lifecycle.tool.before(order=-50)
async def restrict_warehouse_writes(context, request):
    """Require approved naming for model-selected warehouse writes."""
    if context.tool_name.startswith("warehouse_write_"):
        return context.finish({"error": "use_an_approved_write_tool"})
    return context.next()
```

Root `lifecycle/` files and extension `lifecycle/` files sort together by `order` (lowest first), then extension dependency order, then source path. Duplicate singleton authorities (such as two `@lifecycle.output_policy` definitions) fail compilation.

See [Manifest (`extension.yaml`)](/harnest/build/extensions/manifest#capabilities-reference) for every capability name.

## Audit committed mutations

Wrap writes triggered by users or agents with [`extension_mutation(...)`](/harnest/reference/api/extensions#extension_mutation) to emit correlated, payload-free OpenTelemetry audit events (no arguments, credentials, or return values are logged):

```python extensions/warehouse/extension.py
from harnest.extensions import extension_mutation

async def _create_export(self, query_id: str):
    async with extension_mutation("warehouse", "export.create", trigger="agent"):
        return await self._client.create_export(query_id)
```

For external work that outlives a single process or replica, declare `context.continuations` and follow [Durable execution](/harnest/runtime/durable-execution).
