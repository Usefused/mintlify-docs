Agent Skills provide task-specific instructions on demand. Use filesystem skills for versioned guidance or a [`SkillSource`](/harnest/reference/api/skills#skillsource) for a catalog that changes without redeployment.

| Property | Rule |
|---|---|
| Location | `skills/<name>/SKILL.md` |
| Name | Kebab-case and equal to the directory name |
| Loading | On demand through one source registry |
| Optional resources | `references/`, `assets/`, and `scripts/` |
| Ownership | Root agent or one folder SubAgent |

Each skill uses the Agent Skills directory format:

```text
skills/
└── triage-incidents/
    ├── SKILL.md
    ├── references/
    └── scripts/
```

Keep `SKILL.md` action-oriented. Move schemas, background, long examples, and conditional detail into referenced files.

## Runtime behavior

ADK and LangGraph receive the same `list_skills`, `load_skill`, and `load_skill_resource` tools. `list_skills` returns each skill's source, ID, name, description, and version. Skill bodies and resources load only after selection.

Harnest ranks filesystem skills by name and description, then reranks bounded candidates across sources. If a query finds nothing, it ranks one fallback page without loading skill bodies.

A root skill belongs to the root agent. A folder SubAgent can own private skills; its parent does not inherit them. Skills do not add tools or MCP connections.

Use an [Agent Plugin](/harnest/build/agent-plugins) to distribute reusable skills, optionally with the MCP servers that supply their operations. Skills-only plugins are supported.

## Automatic selection with decisions

Enable decision-backed skill selection on an individual managed [`Agent`](/harnest/reference/api/agent#agent). It works with ADK and LangGraph and is off by default:

```python agent.py
from harnest.agent import Agent
from harnest.skills import DecisionSkillSelector, SkillContext

def selection_input(context: SkillContext):
    return {
        "task": context.task,
        "product": context.state.get("product"),
    }

root_agent = Agent(
    name="support",
    model="openai/gpt-4.1-mini",
    skill_selection=DecisionSkillSelector(
        provider="jev",
        instructions="Select skills needed for the task and product; skip unrelated skills.",
        input=selection_input,
        max_skills=3,
        max_candidates=30,
        fallback=DecisionSkillSelector.DISCOVERY,
    ),
)
```

Register the provider in the root `decisions` context resource using the existing [decision-provider contract](/harnest/build/models-and-libraries/typed-decisions/providers). The selector can use [Jev](/harnest/build/models-and-libraries/typed-decisions/jev) or another provider; it does not construct a client or read provider credentials. A registry used only for skill selection can have `bindings=()` because Harnest builds its definitions dynamically. Omit `provider` when the registry contains exactly one provider; otherwise specify its registered name.

### What reaches the decision provider

Selection uses the current agent’s authorized catalog, including filesystem, plugin, extension, and dynamic sources.

Each candidate becomes a [`Choice`](/harnest/reference/api/decisions#choice) question with `select` and `skip` outcomes. The provider must support `QuestionKind.CHOICE` and, for multiple candidates, batching. Questions include candidate identity, version, description, and selection instructions.

The input callback receives the existing **[`SkillContext`](/harnest/reference/api/skills#skillcontext)**, not a separate selection context. During automatic selection, `context.task` is the current textual task and `context.state` is a read-only JSON snapshot of session/native application state with conversation messages and private Harnest channels excluded. These two properties are unavailable outside that selection scope. Existing identity, claims, storage, credential resolution, and exported resources retain their usual access boundaries.

The callback may be synchronous or asynchronous and must return a JSON-compatible mapping. Its return value is the complete `DecisionRequest.state["input"]` payload; Harnest does not merge additional task, identity, metadata, history, or state into it. Without a callback, this payload is just `{"task": context.task}`. Candidate questions are constructed separately, so a callback field cannot replace the authorized candidates. Skill bodies are not sent to the decision provider.

### Loading and fallback

Exact `$skill-id` mentions within the visible candidate page are loaded before automatic choices, up to `max_skills`. Normal skill tools remain available, including when the model needs to follow another explicit request or discover candidates beyond the bounded page. Automatic selection does not grant tools, execution permission, or access to another agent's skills.

Selected instructions are added to model requests, not session history, and reused for the same agent and task within an invocation. Later invocations rediscover the catalog. Catalog order breaks ties above `max_skills`; selecting none is valid.

`timeout_seconds` defaults to 10 and bounds discovery, input preparation, provider evaluation, and loading together. The registered decision provider's own timeout also applies. Failures fall back to normal discovery with `DecisionSkillSelector.DISCOVERY`; choose `DecisionSkillSelector.ERROR` to stop with a redacted [`SkillSelectionError`](/harnest/reference/api/skills#skillselectionerror). These are [`SkillSelectionFallback`](/harnest/reference/api/skills#skillselectionfallback) enum members; string values are rejected. Cancellation propagates and existing version pins are never silently replaced.

## Dynamic sources

Implement `SkillSource` in `harnest.lib` when skills come from an API or database:

```python lib/wex.py
from harnest.skills import SkillSource

class WexSkillSource(SkillSource):
    async def list(self, context, *, query=None, cursor=None, limit=50): ...
    async def load(self, skill_id, context, *, version=None): ...
```

Register it once in `lifecycle/`:

```python lifecycle/skills.py
from harnest.lib.wex import WexSkillSource
from harnest import lifecycle

@lifecycle.skills.source("wex")
def wex():
    return WexSkillSource()
```

The factory runs during compilation but must not query the remote catalog. `list`, `load`, and `load_resource` run inside an invocation and receive `SkillContext` with the active agent, verified user and non-secret claims, session, credentials, storage, and resources.

<Note>
  Apply authorization, search, ordering, and pagination in the source. Return only descriptors visible to [`context.agent_name`](/harnest/reference/api/context#agentcontext), `context.user_id`, and `context.claims`.
</Note>

[`SkillSource.list(query=...)`](/harnest/reference/api/skills#skillsource-list) can use your database’s text or vector search. Return the strongest candidates first; your application owns embedding costs, indexing, privacy, and invalidation.

Application code accesses the same registry through [`context.skills`](/harnest/reference/api/skills#skillaccess). Loaded versions stay pinned for the invocation.

## Authoring skill versus runtime skills

`harnest skills install` installs coding-agent guidance outside the agent's runtime `skills/` directory. It does not add runtime skills to the compiled agent.

| Bundled skill | Use it to |
| --- | --- |
| `harnest-authoring` | Build, modify, and verify agent source. |
| `harnest-authentication` | Configure authentication and credential boundaries. |
| `harnest-studio` | Configure Studio workspaces, company packs, and builder settings. |
| `harnest-studio-ui` | Customize Studio themes, layouts, sections, and UI frameworks. |

```bash
harnest skills install --target codex --project .
harnest skills show harnest-studio
harnest skills show harnest-studio-ui
```

Installation includes each skill's linked references. Targets include `agents`, `claude`, `codex`, `copilot`, and `cursor`; omit `--target` for automatic detection. Existing installations are preserved unless you pass `--force` to replace the bundled skills. For Studio examples, see [company packs](/harnest/studio/packs) and [UI customization](/harnest/studio/mods).
