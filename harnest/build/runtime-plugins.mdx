A Runtime Plugin adapts an SDK or external service to Harnest. It runs in the agent process and can contribute declared lifecycle, context, storage, HTTP, content, and telemetry capabilities.

Building one is a three-part process: define the plugin's application-owned object, declare how it joins Harnest lifecycle, then consume its bounded API from agent code.

<Steps>
  <Step title="Create the plugin">
    Add `plugins/<name>/plugin.yaml`, export the singleton from `plugin.py`, and declare any SDK dependencies.

    <Card title="Create a Runtime Plugin" icon="puzzle-piece" href="/harnest/build/runtime-plugins/create">
      Build the folder, manifest, typed context, and shared dependency contract.
    </Card>
  </Step>
  <Step title="Integrate lifecycle behavior">
    Own application startup and shutdown in the plugin class. Put declared Harnest hooks and factories under the plugin's `extensions/` directory.

    <Card title="Use lifecycle in a plugin" icon="arrows-rotate" href="/harnest/build/runtime-plugins/lifecycle">
      Declare capabilities, ordering, hooks, storage, telemetry, and auditing.
    </Card>
  </Step>
  <Step title="Use the plugin from the agent">
    Import its compiler-owned namespace or resolve its typed invocation context. No central registry is required.

    <Card title="Use a Runtime Plugin" icon="plug" href="/harnest/build/runtime-plugins/use">
      Discover local plugins, call their public API, and understand PyPI search behavior.
    </Card>
  </Step>
</Steps>

## Choose the right plugin boundary

| Need | Use |
|---|---|
| Reuse MCP tools and the guidance for choosing them | [Agent Plugin](/harnest/build/agent-plugins) |
| Wrap an SDK in typed, invocation-scoped Python | Runtime Plugin |
| Apply behavior to one application without a reusable plugin API | Root lifecycle extension |
| Run work outside the agent process | Runtime Plugin backed by an external service |

<Warning>
  Runtime Plugins share the root interpreter, event loop, dependency solve, and lock. They do not receive plugin-private environments, and they do not turn an external job into a resumable Python process.
</Warning>
