Use fixed Cron schedules for application-owned recurring work, such as nightly cleanup. Schedules ship with your code and work in both frameworks.

Use [Dynamic schedules](/harnest/build/dynamic-schedules) when a user chooses the timing or needs to pause and change a schedule at runtime. Use a [delayed Task](/harnest/build/queued-tasks#make-retries-safe) for a one-time run.

## Declare a schedule

Define a function with [`@cron`](/harnest/reference/api/cron#cron-decorator) in `cron/`. Harnest creates its queued task; you do not need a separate `tasks/` file. This example runs at **09:00 UTC, Monday–Friday**:

```python cron/daily_report.py
from harnest.cron import cron

@cron(
    "0 9 * * 1-5",
    arguments={"account_id": "acct_123"},
    queue="reports",
    max_retries=3,
)
async def daily_report(account_id: str) -> dict:
    """Build one account report on the reports queue."""

    return {"account_id": account_id, "status": "ready"}
```

Use a synchronous or asynchronous function with a docstring. Arguments must match its signature and contain only JSON-safe values. A direct call to the decorated function runs inline. For a function scheduled only by users at runtime, omit the fixed expression and use [Dynamic schedules](/harnest/build/dynamic-schedules).

Put one schedule in each root `cron/<name>.py` file and match the export to the filename: `daily_report.py` defines `daily_report`. Nested folders are unsupported; names beginning with `_` or `.` are ignored. You do not need to import schedules in `agent.py`.

## Reuse an existing Task

Use [`Cron`](/harnest/reference/api/cron#cron) when you already have a Task or want multiple fixed schedules for the same work. With the shared `build_report` task from [Create and run Tasks](/harnest/build/queued-tasks#define-and-call-a-task), a declaration looks like this:

```python cron/daily_report.py
from harnest import cron
from harnest.lib.report_tasks import build_report

daily_report = cron.Cron(
    "0 9 * * 1-5",
    task=build_report,
    arguments={"account_id": "acct_123"},
)
```

Choose either this declaration or the decorated function for `daily_report.py`. See the [Cron API reference](/harnest/reference/api/cron) for constructor fields, decorator parameters, and expression constraints.

## Run the scheduler

Register the **same durable storage instance** with [`@lifecycle.storage.tasks`](/harnest/reference/api/lifecycle#storage-tasks) and [`@lifecycle.storage.cron`](/harnest/reference/api/lifecycle#storage-cron) using [Task and cron storage](/harnest/runtime/task-storage), then run:

```bash
harnest serve .
```

Keep the serving process running. `harnest run` does not activate schedules. Replicas sharing the provider coordinate occurrence submission through storage.

## Plan for retries and permissions

Schedules use five cron fields and **UTC only**. Account for daylight-saving changes if your users expect a fixed local time.

A scheduled occurrence queues a Task, and workers may retry it. Make the task's effects idempotent even though the shared provider atomically commits each occurrence. See [Make retries safe](/harnest/build/queued-tasks#make-retries-safe).

Fixed schedules run with Harnest's automation identity. If a scheduled task invokes an agent that needs governed tools or MCP operations, supply an explicit [service principal](/harnest/runtime/agent-runtime-principals).

## Change a schedule

Edit the application declaration and deploy it through your normal workflow. A fixed [`Cron`](/harnest/reference/api/cron#cron) declaration has no runtime pause or cancel methods. For user-controlled schedules, create a [`CronJob`](/harnest/reference/api/cron#cronjob) through the [dynamic schedule API](/harnest/build/dynamic-schedules).
