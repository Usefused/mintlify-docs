Use `models/` for shared Pydantic contracts and `lib/` for reusable Python. Neither folder is scanned for capabilities.

| Folder | Put here | Import from | Discovered as a capability? |
|---|---|---|---:|
| `models/` | Pydantic contracts | `harnest.models` | No |
| `lib/` | Reusable Python | `harnest.lib` | No |

## `models/`

Import root `models/` files through `harnest.models`. For example:

```python models/orders.py
from pydantic import BaseModel

class OrderStatus(BaseModel):
    order_id: str
    status: str
```

Use these contracts for agent, graph, tool, and client-tool input or output. The folder is root-only and needs no `__init__.py`.

## `lib/`

Import root `lib/` files through `harnest.lib`. Keep discovered tools in `tools/`:

<Steps>
  <Step title="Create lib/storage/queries.py">
```python lib/storage/queries.py
def load_order(order_id: str) -> dict:
    """Load one order from application storage."""

    return {"order_id": order_id, "status": "processing"}
```
  </Step>
  <Step title="Create tools/lookup_order.py">
```python tools/lookup_order.py
from harnest.lib.storage.queries import load_order
from harnest.agent import tool

@tool
def lookup_order(order_id: str) -> dict:
    """Load one order."""

    return load_order(order_id)
```
  </Step>
</Steps>

These imports work in compilation, tests, evaluations, and serving. `lib/` is root-only.

Add third-party packages used by either namespace to the agent's `pyproject.toml`. Add `__init__.py` only for intentional library initialization, not to make discovery work.
