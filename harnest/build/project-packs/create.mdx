A **pack** is a folder containing `pack.yaml`, optional `pack.py` hooks, and any templates, skills, wheels, extensions, or Studio assets you want to ship to your teams.

<Steps>
  <Step title="Generate a starter pack">
    ```bash
    harnest pack init acme --output ./acme-pack
    ```

    Omit `--output` to create `./acme-pack`. Pack names use lowercase letters, digits, or hyphens, start with a letter, and contain at most 63 characters (`harnest` is reserved).

    ```text
    acme-pack/
      pack.yaml                        # identity, command name, and bundled capabilities
      pack.py                          # optional init, migration, and custom command hooks
      templates/
        harnest-compile.yaml           # starter compile-selection file copied into new agents
        team-guide.md                  # starter teammate guide copied to docs/team-guide.md
    ```
  </Step>

  <Step title="Review pack.yaml">
    The generated `pack.yaml` starts with the required metadata and the branded CLI command name:

    ```yaml pack.yaml
    apiVersion: harnest.dev/pack/v1
    name: acme
    version: 0.1.0
    title: acme agents
    description: Company defaults for new acme agents.
    command: acme
    ```

    See [Manifest (`pack.yaml`)](/harnest/build/project-packs/manifest) for a complete example showing every optional field (`requires`, `skills`, `packages`, `extensions`, and `studio`).
  </Step>

  <Step title="Validate and build the pack">
    ```bash
    harnest pack validate ./acme-pack
    harnest pack build ./acme-pack --output ./dist
    ```

    Produces a standalone `./dist/acme` binary (`./dist/acme.exe` on Windows) with Harnest and your pack embedded. For a Python launcher wheel (`--format wheel`) or cross-stamping (`--base-binary`), see [Run and ship](/harnest/build/project-packs/cli).
  </Step>

  <Step title="Test the branded binary on a new agent">
    Use your built binary to scaffold a new agent and compile that agent:

    ```bash
    ./dist/acme init ./sales
    ./dist/acme compile ./sales --format executable --output ./dist/sales-agent
    ```

    While iterating locally before building a binary, you can also test the pack folder directly with `harnest init ./sales --pack ./acme-pack`.
  </Step>
</Steps>

<Note>
**Pack vs. agent commands:** `harnest pack build` builds a **pack folder** (`pack.yaml`) into a branded CLI binary. `compile` only compiles an **agent folder** (`config.yaml`)—running `harnest compile` inside a pack folder fails with a missing `config.yaml` error.
</Note>
