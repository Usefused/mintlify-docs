Use [`ProjectCLI`](/harnest/reference/api/authoring#projectcli) to expose your installed packs through a company-owned executable. It uses the same planning API available to custom interfaces.

## Register the entrypoint

```python cli.py
from harnest.authoring import ProjectCLI
from acme_agent_pack.pack import pack

cli = ProjectCLI(name="acme-agent", packs=[pack])

def main() -> int:
    return cli.run()
```

Register `main` as a console script in your company package:

```toml pyproject.toml
[project.scripts]
acme-agent = "acme_agent_pack.cli:main"
```

The `packs` order is the execution order. Their names must be unique. Install the Harnest executable alongside the company CLI, or select it explicitly:

```python
cli = ProjectCLI(
    name="acme-agent",
    packs=[pack],
    harnest_command=("/approved/path/harnest",),
)
```

Pin that executable and the Python Harnest package to the same release. Initialization uses the executable's scaffold; upgrades use the Python migration engine.

## Commands and flags

| Command | Default behavior | Additional flags |
|---|---|---|
| `init DIRECTORY` | Plan and apply to an absent or empty directory. | `--dry-run`, `--framework adk\|langgraph`, `--mode managed\|advanced`, `--minimal`, `--example`, `--template`, `--template-sha256`, `--json`, pack options. |
| `upgrade DIRECTORY` | Print a read-only combined plan. | `--apply`, `--json`, pack options. |

```sh
acme-agent init support-bot --team customer-success --dry-run --json
acme-agent init support-bot --team customer-success
acme-agent upgrade support-bot
acme-agent upgrade support-bot --apply
```

A later `--apply` command builds a fresh plan; the CLI does not persist and replay an earlier preview. `--json` prints a plan without file contents or option values. It can be combined with application flags and does not itself make the command read-only.

| Exit code | Meaning |
|---|---|
| `0` | Success, including a plan with no changes. |
| `1` | Operational error. |
| `2` | Blocked plan or invalid command-line arguments. |

## Initialize from a template

Pass a Harnest template to your team's CLI:

```bash
acme-agent init ./sales --template acme-sales --team sales
```

`--template` accepts the same template project name, short slug, or HTTPS wheel URL as `harnest init`. For an HTTPS wheel, optionally pin its contents:

```bash
acme-agent init ./sales \
  --template https://packages.example.com/acme_sales.whl \
  --template-sha256 "$TEMPLATE_SHA256" \
  --team sales
```

Harnest renders the template in staging, then runs pack initializers. The template determines framework, mode, and initial files; pack ownership rules govern later changes.

`--template` cannot be combined with an explicit `--framework`, `--mode`, `--minimal`, or `--example`. `--minimal` and `--example` are mutually exclusive. `--template-sha256` requires `--template`. Without a template, the framework still defaults to ADK and mode to managed.

Use `--dry-run` to review changes without creating the destination. Planning may download the template; download or validation failures stop before pack hooks run.

## Typed pack options

Declare a Pydantic options model when [creating the pack](/harnest/build/project-packs/create). String, integer, and number fields become typed flags. Enums become choices; defaults and validation remain in the Pydantic model.

| Model input | CLI example |
|---|---|
| String | `--team customer-success` |
| Integer | `--replicas 2` |
| Enum | `--environment production` |
| Boolean | `--enabled true` |
| List or object | `--regions '["eu-west", "us-east"]'` |

Use explicit JSON literals for booleans and structured inputs. Avoid field names reserved by the CLI, such as `framework`, `mode`, `minimal`, `example`, `template`, `template_sha256`, `json`, and `apply`.

With multiple packs, flags gain the pack name prefix: `--acme-team`, `--platform-region`. Underscores in field names become hyphens in flags.

Options are validated before that pack's callbacks execute and are not stored in `harnest-packs.lock`. During upgrades, a pack receives `context.options = None` unless its options were supplied; read persisted company choices from its configuration file.

## Add a company command

`add_command` returns an `argparse.ArgumentParser`. Add your arguments and return an integer exit code from the handler:

```python
import argparse
from pathlib import Path

def inspect_company_file(arguments: argparse.Namespace) -> int:
    path = arguments.directory / "acme-agent.yaml"
    print(f"Company configuration: {path}")
    return 0 if path.is_file() else 1

parser = cli.add_command(
    "inspect-company", inspect_company_file,
    help="Locate this agent's company configuration",
)
parser.add_argument("directory", type=Path)
```

Custom handlers own their work and error handling; they do not automatically participate in the project transaction. Other Harnest commands are not automatically forwarded unless you register Studio as described below. You can also expose them through explicit company handlers.

`cli.run(arguments, stdout=..., stderr=...)` supports embedded callers and tests. It returns an exit code for normal command execution; argparse retains its usual exit behavior for help and invalid arguments.

## Include your company's Studio

The same company CLI can launch Studio with its bundled [UI and resource packs](/harnest/studio/packs):

```python acme_cli/__init__.py
from pathlib import Path
from harnest.authoring import ProjectCLI
from acme_cli.pack import pack

def main() -> int:
    cli = ProjectCLI("acme", [pack])
    cli.add_studio(
        command=("acme",),
        packs=[Path(__file__).parent / "studio"],
        # If the project pack requires a team option:
        init_args=("--team", "support"),
        # Only for packs containing JavaScript modules you trust:
        # trusted_ui=("acme-ui",),
    )
    return cli.run()
```

`studio/` contains `studio-pack.yaml` and its declared assets. Include the directory in your wheel as package data; resolve it relative to your installed module so launch does not depend on the current directory. `command` is an argv sequence, never a shell string. For a Python module entrypoint it can be `(sys.executable, "-m", "acme_cli")`, provided that module is executable.

Register the executable and an optional Studio dependency in the company package:

```toml pyproject.toml
[project.scripts]
acme = "acme_cli:main"

[project.optional-dependencies]
studio = ["harnest-agent-builder==0.1.0"]
```

Pin compatible Harnest and Studio releases when publishing. This integration must be present in the Harnest SDK version you distribute. The package does not embed Python or the native Harnest executable.

```bash
pip install 'acme-agent-pack[studio]'
acme init support-bot --team support
acme studio --workspace .
```

Studio's **Create agent** action invokes `acme init`, including its initialization hooks and the configured `init_args`. Command previews and job output show the company command. Use non-secret team defaults in `init_args`; they appear in the UI and process arguments. The standard creation dialog does not generate fields for arbitrary pack options. Use defaults or a custom UI when those choices need to vary.

Registering Studio also exposes `add`, `compile`, `test`, `env`, `serve`, `run`, `extensions`, and `provision` through the company CLI. These delegate to its configured `harnest_command`, preserving argv and exit codes. Register custom handlers **before** `add_studio` to retain ownership of those names. Forwarded processes inherit terminal streams; `run(stdout=..., stderr=...)` captures project-plan output, not delegated subprocess output.

Ordinary `acme init` and `acme upgrade` do not import Studio. `acme studio` reports an installation error if the optional dependency is missing. Studio's existing deployment gates and explicit JavaScript trust requirements still apply.

`acme studio --safe-ui` removes external Studio packs while keeping company CLI initialization. The Studio Packs catalog's template installation remains a separate reviewed resource-installation flow; it does not run CLI pack initialization hooks. Use **Create agent** for company CLI initialization.
