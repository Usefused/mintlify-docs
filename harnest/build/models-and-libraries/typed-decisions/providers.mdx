Implement [`DecisionProvider`](/harnest/reference/api/decisions#decisionprovider) in your application or a Harnest Extension. Register the instance in [`Decisions(providers={...}, bindings=(...))`](/harnest/reference/api/decisions#decisions); each [`DecisionBinding`](/harnest/reference/api/decisions#decisionbinding) selects a provider by name. For a complete adapter, see [Use Jev](/harnest/build/models-and-libraries/typed-decisions/jev).

## Provider contract

Implement [DecisionProvider](/harnest/reference/api/decisions#decisionprovider) and declare its [capabilities](/harnest/reference/api/decisions#decisioncapabilities).

Only advertise guarantees your provider consistently supplies, including supported question kinds, batching, probabilities, and confidence.

Capabilities apply to the whole provider. Use separate registrations for models with different guarantees. Unsupported question types, duplicate decision names, unknown providers, and incompatible policies fail when the registry is constructed.

## Requests and results

The [request and result reference](/harnest/reference/api/decisions#request-and-result-validation) defines accepted answer shapes and validation for each question kind.

Convert immutable request state into your SDK's payload format. Return probabilities and confidence exactly when declared; Harnest rejects non-finite values, invalid distributions, missing or extra answers, and out-of-domain results. A provider's score is preserved without assuming a scoring formula.

Batch independent questions together when supported. If a question needs an earlier answer, make a separate evaluation with new state. Harnest does not split batches automatically.

## Policies

Use [ChoicePolicy](/harnest/reference/api/decisions#choicepolicy) to map every choice to an outcome, or [ThresholdPolicy](/harnest/reference/api/decisions#thresholdpolicy) for lower, upper, and uncertain bands.

Threshold defaults are block, proceed, and abstain. Predicate thresholds use the `0–1` probability scale; score thresholds use rubric positions. A score's middle band is an authored rule, not model uncertainty. Confidence meanings and suitable thresholds can differ between providers.

[`DecisionOutcome`](/harnest/reference/api/decisions#decisionoutcome) accepts `ROUTE`, `PROCEED`, `BLOCK`, `REVIEW`, `REASON`, or `ABSTAIN`. Only `ROUTE` takes a destination. Your application performs the selected action through its usual authorization and approval boundaries.

## Failures and deadlines

| Failure | Default exception | Evaluation error with `on_error` |
|---|---|---|
| Provider fails | [`DecisionProviderError`](/harnest/reference/api/decisions#decisionprovidererror) | `provider_error` |
| Evaluation times out | [`DecisionTimeoutError`](/harnest/reference/api/decisions#decisiontimeouterror) | `timeout` |
| Response violates the contract | [`DecisionValidationError`](/harnest/reference/api/decisions#decisionvalidationerror) | `invalid_response` |

All three derive from [`DecisionError`](/harnest/reference/api/decisions#decisionerror). Set `DecisionBinding.on_error` to an explicit block, review, reasoning, or abstention outcome to receive `response=None` instead. Failure policies cannot proceed or route. Caller cancellation always propagates.

`Decisions(timeout_seconds=...)` uses a cooperative asynchronous deadline. Providers must propagate cancellation and set network timeouts. Harnest adds no retries or caching; configure any SDK retries explicitly.

## Resource ownership

Publish the registry with [`@context.provider("decisions")`](/harnest/reference/api/context#provider). Use [`@lifecycle.resource`](/harnest/reference/api/lifecycle#resource) and a context manager to own provider-client startup and cleanup; `Decisions` does not close them.

An extension can contribute this lifecycle resource with `context.resources`, or expose a provider factory for the application to register. Keep one owner for the registry when combining providers. See [Harnest Extensions](/harnest/build/extensions).

Definitions are shared application resources, including for subagents; they are not per-agent permission grants. [`context.decisions`](/harnest/reference/api/decisions#decisioncontext) rejects retained facades used by another agent or invocation, or after the owning invocation ends.

## Public decision results

[`context.decisions.evaluate(...)`](/harnest/reference/api/decisions#decisioncontext-evaluate) always returns [`DecisionEvaluation`](/harnest/reference/api/decisions#decisionevaluation). [`OutputPolicy(decision_results=True)`](/harnest/reference/api/output#outputpolicy) additionally publishes an event. Direct [`Decisions.evaluate(...)`](/harnest/reference/api/decisions#decisions-evaluate) calls do not emit public events.

Use the [output-policy reference](/harnest/runtime/lifecycle/output-policy#choose-decision-results) to configure disclosure. Decision events are separate from the privacy-safe telemetry described below.

## Offline tests and telemetry

Use [`FixtureDecisionProvider`](/harnest/reference/api/decisions#fixturedecisionprovider) as shown in the [quickstart](/harnest/build/models-and-libraries/typed-decisions). Missing fixtures or changed definition versions fail without contacting a live provider. Fixtures exercise validation and orchestration; use labeled datasets separately to measure model quality.

`harnest.decision.evaluate` spans record definition/provider identities, revisions, duration, outcome, and policy action. They exclude payloads and provider errors. Keep sensitive data out of authored identities.
