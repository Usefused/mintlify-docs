Configure `TokenPolicy` per managed agent to observe usage, enforce budgets, or reduce model context. These controls are independent and off unless configured.

## Start with observation

Add a policy to your existing agent definition:

```python agent.py
from harnest.agent import Agent
from harnest.model import LiteLLMModel
from harnest.tokens import TokenPolicy

root_agent = Agent(
    name="support",
    model=LiteLLMModel.from_openai_environment(),
    token_policy=TokenPolicy(),
)
```

[`TokenPolicy()`](/harnest/reference/api/tokens#tokenpolicy) observes without changing or blocking requests. Numeric reports go to [`harnest.tokens`](/harnest/reference/api/tokens) at INFO level or your `observer`; prompt and tool-result content is excluded.

You can set budgets while leaving `enforce=False` to observe which input, context-window, and model-call budgets would be exceeded. An output limit is passed to the provider only when enforcement is enabled.

## Choose limits and reductions

```python
from harnest.tokens import TokenPolicy

policy = TokenPolicy(
    observe=True,
    enforce=True,
    max_input_tokens=24_000,
    context_window=32_000,
    reserve_output_tokens=4_000,
    max_output_tokens=2_000,
    max_model_calls=8,
    keep_recent_turns=6,
    max_tool_result_chars=4_000,
)
```

Pass this object as [`Agent(token_policy=policy, ...)`](/harnest/reference/api/agent#agent). These numbers are examples, not defaults. Configure each graph agent or subagent independently; a parent's policy does not automatically configure its children or native targets.

See [TokenPolicy settings and defaults](/harnest/reference/api/tokens#policy-settings) for every option. Start with observation, then enable only the limits and reductions your workload needs.

Reductions run when you explicitly configure them, even if `enforce=False`. To observe unchanged requests, leave all reductions and transforming callbacks unset.

<Note>
The default counter estimates serialized input at four characters per token. Reports mark these counts as estimates. Provider framing, language, media, and generated tool schemas can change actual usage. Supply a model-aware `count_tokens` callback when you need accurate admission checks. A count-based input budget is not a guaranteed billing cap.
</Note>

Budgets are checked after reductions, before dispatch. Violations raise [`TokenBudgetExceeded`](/harnest/reference/api/tokens#tokenbudgetexceeded). In a stream, earlier output may already have reached the caller.

Model-call counts are shared per agent within an invocation and reset on new or resumed invocations. Provider-internal retries are excluded; these are not durable spending limits.

## Keep the original history

Reductions affect only the model request. Session history, checkpoints, and original tool results remain unchanged.

The built-in history reduction removes complete earlier turns. It keeps the latest user turn and its ongoing tool exchanges together, and preserves system/developer instructions. It does not generate summaries. Tool-text reduction preserves identifiers and structured scalar types, and leaves LangGraph non-text media blocks intact. ADK JSON response string values are shortened individually.

Compare task success, retries, latency, and token usage before enabling reductions. Use a custom transformation for summaries or selective retention.

## Override or disable for one invocation

Use a trusted Python scope around runtime calls:

```python
from dataclasses import replace
from harnest.tokens import token_policy_scope

# `driver` and `request` are your existing Harnest runtime objects.
with token_policy_scope(None):
    result = await driver.invoke(request)

with token_policy_scope(replace(policy, max_model_calls=12), agent_name="support"):
    async for event in driver.stream(request):
        handle_event(event)
```

The scope applies to child tasks and restores the previous configuration on exit. Agent-specific overrides take precedence over scope-wide overrides. Keep the scope open for the entire consumption of a stream.

An agent must have an adapter installed before a scope can enable policy for it. Use `Agent(token_policy=TokenPolicy(enabled=False), ...)` to install a disabled adapter for later activation. `Agent(token_policy=None, ...)`, the default, installs no adapter at all.

Only trusted Python code can change token policy; HTTP metadata cannot. Authenticate callers before selecting a profile. Outside Harnest invocations, use [`token_policy_scope(...)`](/harnest/reference/api/tokens#token_policy_scope) for `max_model_calls` state.

## Supply your own strategies

All strategy callbacks accept ordinary or asynchronous functions. Synchronous model calls require synchronous strategies. Harnest does not call an additional model unless your strategy does so.

Choose a [strategy callback](/harnest/reference/api/tokens#strategy-callbacks) when built-in counting, retention, or tool selection does not fit your workload.

Harnest counts input, applies built-in reductions, runs `request_transform` and `tool_selector`, recounts, then checks budgets. Selection preserves tool order and cannot add permissions.

For example, restrict exposed tools using an application-owned set:

```python
from harnest.tokens import TokenPolicy, TokenRequest, TokenReport

allowed_tools = {"lookup_order", "search_help"}

def select_tools(request: TokenRequest) -> list[str]:
    """Expose the tools selected for this application profile."""
    return [tool["name"] for tool in request.tools if tool["name"] in allowed_tools]

def record_usage(report: TokenReport) -> None:
    """Forward numeric observations to your metrics sink."""
    print(report)

policy = TokenPolicy(tool_selector=select_tools, observer=record_usage)
```

[`TokenRequest`](/harnest/reference/api/tokens#tokenrequest) uses native message and system formats: Google `Content` dictionaries for ADK and LangChain `messages_to_dict` for LangGraph. Branch on `framework` when transforming native settings. See [TokenRequest fields](/harnest/reference/api/tokens#tokenrequest).

Transformations may edit messages, instructions, and generation settings. They must preserve tool-call/result pairing, required instructions, and native metadata. Use `tool_selector` to select tools; `context_metadata` is read-only counter input.

[`TokenReport`](/harnest/reference/api/tokens#tokenreport) separates counted input from provider-reported usage; unavailable usage stays `None`. Observer failures log a warning without interrupting execution. See [report fields](/harnest/reference/api/tokens#tokenreport).

## Framework coverage

Policies apply to configured managed agents in ordinary and streaming calls. Native targets and model calls inside your own Python need separate integration.

Disable token policy for ADK live connections, which reject active policies. Configure provider caching and reasoning through model settings or your request transformation.

See [Agents and graphs](/harnest/build/agents-and-graphs), [Lifecycle](/harnest/build/extensions/lifecycle), and [Telemetry](/harnest/runtime/telemetry) for the surrounding runtime contracts.
