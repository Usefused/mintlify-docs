A **Harnest Extension** is a folder (`extensions/<name>/`) containing `extension.yaml`, `extension.py`, and optional Python dependencies or contributed resources. It runs inside the agent process and shares the agent's Python environment.

```text
extensions/warehouse/
  extension.yaml     # identity, entrypoint, capabilities, and contributed folders
  extension.py       # Extension singleton (and optional start/stop + request context)
  pyproject.toml     # optional SDK dependencies (merged into harnest-runtime.lock)
  tools/             # optional managed Agent Tools
  lifecycle/         # optional hooks, policies, storage, or HTTP routes
```

## Ways to add an extension

```bash
# 1. Install from PyPI (short slug or full harnest-extension-* name)
harnest extensions install docker
harnest env sync .

# 2. Install from a local directory
harnest extensions install ../warehouse
harnest env sync .

# 3. Scaffold a new extension inside your agent
harnest extensions init warehouse
```

Platform teams can also auto-attach extensions to every compiled agent without copying files into agent repos by listing them under `extensions:` in a [Harnest Pack](/harnest/build/project-packs/capabilities#enforce-policies-with-pack-owned-extensions).

## Choose the right boundary

| Need | Use |
|---|---|
| Portable skills and declarative `mcp.json` (no Python code) | [Agent Plugin](/harnest/build/agent-plugins) |
| Reusable Python SDK wrapper, tools, policies, storage, HTTP routes, or sandbox provider | **Harnest Extension** |
| One-off hooks or storage for a single agent | Root `lifecycle/` folder |
| Enforce an extension automatically across every company agent | Pack-owned extension in [`pack.yaml`](/harnest/build/project-packs/capabilities#enforce-policies-with-pack-owned-extensions) |

<Warning>
Extensions share the agent's Python interpreter, event loop, and dependency lock (`harnest-runtime.lock`). They do not run in separate virtual environments.
</Warning>
