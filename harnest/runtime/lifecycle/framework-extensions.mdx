title: "Framework extensions"
description: "Connect ADK plugins or LangGraph middleware to the framework selected by Harnest."
---

Use a framework extension when portable lifecycle hooks cannot express the behavior you need. [`@lifecycle.framework_extension`](/harnest/reference/api/lifecycle#framework_extension) decorates a zero-argument factory. Harnest reads `spec.framework.name` from your project configuration and validates each factory's return value against that framework.

| Configured framework | Factory returns | Attachment |
|---|---|---|
| ADK | An ADK `BasePlugin` | ADK `App` plugins, in `order` |
| LangGraph | A LangChain `AgentMiddleware` | Managed agent construction, in `order` |

```python lifecycle/extension.py
from harnest import lifecycle
from google.adk.plugins.base_plugin import BasePlugin

@lifecycle.framework_extension(order=30)
def audit_plugin():
    return BasePlugin(name="audit")
```

Wrong return types and duplicate ADK plugin names fail compilation. Harnest Extensions that contribute these factories declare the `framework.extension` capability.

## Ownership

Harnest keeps authentication, transports, portable lifecycle policy, and storage ownership checks. The framework extension handles framework-specific callbacks. Keep portable behavior in ordinary lifecycle hooks so it can survive a framework switch.

## Advanced mode

| Framework | Discovered framework extensions |
|---|---|
| ADK | Attached after Harnest's credential plugin and the application's existing plugins |
| LangGraph | Rejected. Attach middleware before compiling the graph and wrapping it with `Agent.advanced(...)` |
