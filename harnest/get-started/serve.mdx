From the agent folder, compile and start the standalone development server:

```bash
harnest serve .
```

Send a message from another terminal:

```bash
curl --fail-with-body -sS http://127.0.0.1:1907/responses \
  -H 'Content-Type: application/json' \
  -d '{"input":"Hello! What can you help me with?"}'
```

Read `outputText` and reuse `sessionId` for follow-up turns. See [API requests and streaming examples](/harnest/runtime/serving/neutral-api). Startup prints Swagger and schema URLs; [`server.openapi: false`](/harnest/runtime/serving/server-configuration#hide-api-documentation) hides them.

Normal launches reuse validated artifacts under `.harnest/artifacts/` when source, configuration, locks, and compiler are unchanged. Changed inputs produce a new artifact.

Reload after authored file changes during local development:

```bash
harnest serve . --reload
```

| URL | Use it for |
|---|---|
| `http://127.0.0.1:1907/` | Test the agent in the playground |
| `http://127.0.0.1:1907/docs` | Inspect the generated API |
| `http://127.0.0.1:1907/healthz` | Check process health |

<Note>
  Override the bind, limits, timeout, concurrency, or playground under the optional `server:` section in `config.yaml`. Omit it to use the defaults.
</Note>

See [development reload](/harnest/runtime/serving/development-reload) for restart behavior and [Serving agents](/harnest/runtime/serving) for the HTTP, SSE, WebSocket, approval, authentication, storage, and production boundaries.
