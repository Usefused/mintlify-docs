Install the native CLI and its managed runtime on macOS, Linux, or Windows.

| Property | Value |
|---|---|
| Platforms | macOS, Linux, and Windows |
| Architectures | AMD64 and ARM64 |
| Python required | No |
| Installed command | `harnest` |

<Steps>
  <Step title="Run the installer">
    <Tabs>
      <Tab title="Windows">
        Download the MSI for your system type from [Harnest releases](https://github.com/Usefused/harnest/releases/latest) and double-click it. Choose `harnest_<version>_windows_amd64.msi` for x64 or `harnest_<version>_windows_arm64.msi` for ARM64. You can find your system type in Windows Settings → System → About.

        Follow the installation wizard. It installs the CLI for your user, prepares the runtime, and adds Harnest to your user PATH. Runtime setup may need internet access. Open a new terminal after installation.

        On managed devices, use your organization's software approval process if Windows blocks installation. See [Windows installer](/harnest/reference/installation-and-releases#windows-installer) for repair, upgrades, and uninstall.
      </Tab>
      <Tab title="macOS and Linux">
        ```bash
        curl -fsSL \
          https://raw.githubusercontent.com/Usefused/harnest/main/install.sh |
          sh
        ```
      </Tab>
    </Tabs>

    Review the installation details before confirming.
  </Step>
  <Step title="Verify both layers">
    ```bash
    harnest --version
    harnest doctor
    ```
  </Step>
</Steps>

Run `harnest doctor .` inside a synchronized project to check its framework. Outside a project, `doctor` checks only the core runtime.

<Note>
  A Harnest release includes the native CLI, its matching Python runtime package, and the `uv` bootstrapper. You do not need a preinstalled Python.
</Note>

Installing Harnest adds the CLI and managed runtime; it does not create files in your current directory. Continue to [Initialize a project](/harnest/get-started/initialize) to see the complete folder structure created by `harnest init`.

See [Installation and releases](/harnest/reference/installation-and-releases) for version pinning, non-interactive installation, upgrades, checksums, and private forks.
