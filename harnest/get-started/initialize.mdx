Create a managed agent, prepare its isolated environment, and run the generated tests.

<Steps>
  <Step title="Choose a framework">
    <CodeGroup>

    ```bash ADK
    harnest init support-agent --framework adk
    ```

    ```bash LangGraph
    harnest init support-agent --framework langgraph
    ```

    </CodeGroup>

    The default scaffold is a small, runnable managed agent. Add `--example` for ignored code samples in folders that otherwise contain only guides. The existing agent and storage code stay unchanged.

    The command creates this project structure before it changes or installs anything else:

    ```text support-agent/
    support-agent/
    ├── agent.py
    ├── instructions.md
    ├── config.yaml
    ├── server.yaml
    ├── agent-card.yaml
    ├── pyproject.toml
    ├── harnest.lock
    ├── lib/
    │   └── _README.md
    ├── models/
    │   └── _README.md
    ├── tools/
    │   └── _README.md
    ├── tasks/
    │   └── _README.md
    ├── cron/
    │   └── _README.md
    ├── subagents/
    │   └── _README.md
    ├── mcp/
    │   └── _README.md
    ├── extensions/
    │   ├── _README.md
    │   └── storage.py
    ├── plugins/
    │   └── _README.md
    ├── sandbox/
    │   └── _README.md
    ├── skills/
    │   └── _README.md
    ├── evals/
    │   └── _README.md
    └── tests/
        ├── unit/
        │   └── _README.md
        └── smoke/
            └── _README.md
    ```

    Files beginning with `_` are ignored guides, not enabled capabilities. Replace them with the convention shown inside each guide when you need that feature. `extensions/storage.py` is active and supplies the default in-memory session and checkpoint storage.

    <Note>
      `harnest init` accepts a new directory or an existing empty directory. It refuses a non-empty directory so it cannot overwrite an existing project.
    </Note>
  </Step>
  <Step title="Synchronize the project environment">
    ```bash
    harnest env sync support-agent
    ```

    Synchronization creates `uv.lock` and the generated `.harnest/` environment. Commit `uv.lock`; do not edit or commit `.harnest/`.
  </Step>
  <Step title="Run the offline tests">
    ```bash
    harnest test support-agent
    ```
  </Step>
</Steps>

## What each generated path owns

| Output | Purpose |
|---|---|
| `agent.py` | Root agent or graph |
| `instructions.md` | Agent instructions |
| `config.yaml` | Framework and project settings |
| `server.yaml` | Local server settings |
| `agent-card.yaml` | Public identity, interfaces, and advertised capabilities |
| `pyproject.toml` | Authored dependencies; `harnest env sync` then creates `uv.lock` |
| `lib/` and `models/` | Reusable Python and Pydantic contracts |
| `tools/`, `tasks/`, and `extensions/` | Folder-discovered capabilities and runtime behavior |
| `tests/` | Offline and optional live checks |

With `--example` in managed mode, Harnest adds `_example.py` templates to guide-only Python folders: `lib/`, `models/`, `tools/`, `tasks/`, `cron/`, `subagents/`, `mcp/`, `sandbox/`, `tests/unit/`, and `tests/smoke/`. It does not add another example to `extensions/`, which already contains working storage code, or replace `agent.py`.

Skills, plugins, and evals retain their required formats under ignored paths: `skills/_example/SKILL.md`, `plugins/_example/` for a RuntimePlugin, `plugins/_example_agent/` for an MCP-plus-skills Agent Plugin, and `evals/_example.evalset.json`. Both managed frameworks receive the templates; framework-specific samples identify their restrictions.

Copy or rename only the samples you want to activate. Each Python template names its required destination and dependencies. For example, copy `tools/_example.py` to `tools/echo.py`; activate `tasks/prepare_report.py` before copying the cron sample to `cron/daily_report.py`. The native-format samples have activation instructions in their folder guides. Until then, the samples are not discovered or executed.

Advanced mode keeps native framework wiring in `agent.py` and adds only the examples Harnest still owns. The surrounding folder contract stays the same.

<Note>
  `compile`, `test`, and `serve` sync the environment automatically. Add only your provider, tool, and library packages to `pyproject.toml`; Harnest owns the framework dependency.
</Note>
