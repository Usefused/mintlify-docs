Create a managed agent, prepare its isolated environment, and run the generated tests.

<Steps>
  <Step title="Choose a framework">
    <CodeGroup>

    ```bash ADK
    harnest init support-agent --framework adk
    ```

    ```bash LangGraph
    harnest init support-agent --framework langgraph
    ```

    </CodeGroup>

    The default scaffold is a small, runnable managed agent. Add `--example` for ignored code samples in folders that otherwise contain only guides. The existing agent and storage code stay unchanged.

    Explore the generated project below. Select a file or folder to preview its contents. Folders tagged **optional** can be omitted until you need that capability. Root files show generated contents; optional folders show examples you can add.

    <HarnestProjectExplorer />

    Server defaults work without extra configuration. Add only the settings you want to change under `server:` in `config.yaml`. Set `server.live: true` to enable WebSocket connections on the same HTTP host and port; see [Server configuration](/harnest/runtime/serving/server-configuration).

    Files beginning with `_` are ignored guides, not enabled capabilities. Replace them with the convention shown inside each guide when you need that feature. `lifecycle/storage.py` is active and supplies the default in-memory session and checkpoint storage.

    <Note>
      `harnest init` accepts a new directory or an existing empty directory. It refuses a non-empty directory so it cannot overwrite an existing project.
    </Note>
  </Step>
  <Step title="Synchronize the project environment">
    ```bash
    harnest env sync support-agent
    ```

    Synchronization creates the complete hash-verified `harnest-runtime.lock`, records the exact resolved framework version in `harnest.lock`, and creates the generated `.harnest/` environment. Commit both lockfiles; do not edit or commit `.harnest/`.
  </Step>
  <Step title="Run the offline tests">
    ```bash
    harnest test support-agent
    ```
  </Step>
</Steps>

## What each generated path owns

| Output | Purpose |
|---|---|
| `agent.py` | Root agent or graph |
| `instructions.md` | Agent instructions |
| `config.yaml` | Framework, project settings, and optional `server` overrides |
| `agent-card.yaml` | Public identity, interfaces, and advertised capabilities |
| `pyproject.toml` | Authored dependencies; `harnest env sync` then creates `harnest-runtime.lock` |
| `lib/` and `models/` | Reusable Python and Pydantic contracts |
| `tools/`, `tasks/`, and `lifecycle/` | Folder-discovered capabilities and runtime behavior |
| `tests/` | Offline and optional live checks |

With `--example` in managed mode, Harnest adds `_example.py` templates to guide-only Python folders: `lib/`, `models/`, `tools/`, `tasks/`, `cron/`, `subagents/`, `mcp/`, `sandbox/`, `tests/unit/`, and `tests/smoke/`. It does not add another example to `lifecycle/`, which already contains working storage code, or replace `agent.py`.

Skills, extensions, plugins, and evals retain their required formats under ignored paths: `skills/_example/SKILL.md`, `extensions/_example/` for a Harnest Extension, `plugins/_example_agent/` for an Agent Plugins 1.0 package with `plugin.json`, and `evals/_example.evalset.json`. Both managed frameworks receive the templates; framework-specific samples identify their restrictions. The default `lifecycle/storage.py` already contains working code and needs no extra sample.

Copy or rename only the samples you want to activate. Each Python template names its required destination and dependencies. For example, copy `tools/_example.py` to `tools/echo.py`; activate `tasks/prepare_report.py` before copying the cron sample to `cron/daily_report.py`. The native-format samples have activation instructions in their folder guides. Until then, the samples are not discovered or executed.

Advanced mode keeps native framework wiring in `agent.py` and adds only the examples Harnest still owns. The surrounding folder contract stays the same.

<Note>
  `compile`, `test`, and `serve` sync the environment automatically. Add only your provider, tool, and library packages to `pyproject.toml`; Harnest owns the framework dependency.
</Note>
