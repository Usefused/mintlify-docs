---
title: "Replace one section with Tailwind"
description: "Build a Tailwind welcome panel, load it through a pack, and keep the surrounding Studio interface unchanged."
---

Replace Studio's welcome view with a locally compiled Tailwind CSS panel. The example uses the ordinary [Studio UI pack contract](/harnest/studio/mods). Its frame fills the welcome workspace, and the pack controls the spacing within it.

The example lives in `examples/packs/tailwind-welcome/` in the Harnest source checkout. It replaces `fused-studio/welcome`, shown when no project is selected.

## Build and launch

Use Node.js 20 or newer and npm to build this example. Node is a publisher build dependency; users loading the generated pack do not need it.

```bash
cd examples/packs/tailwind-welcome
npm ci
npm run build
npm run check
harnest pack validate .
mkdir -p /tmp/harnest-tailwind-agents
harnest studio --workspace /tmp/harnest-tailwind-agents --pack .
```

Open Studio's launch URL with no project selected to see the welcome panel. Load one replacement for `fused-studio/welcome` at a time.

The panel displays **Connected to Studio** when it receives the host's connection state.

## Configure the section replacement

```yaml pack.yaml
apiVersion: harnest.dev/pack/v1
name: tailwind-welcome
version: 1.0.0
title: Tailwind welcome
studio:
  resources: []
  ui:
    apiVersion: harnest.dev/studio-ui/v1
    assets: [assets/welcome.html]
    contributions:
      - id: welcome
        title: Tailwind welcome
        slot: welcome
        mode: frame
        entry: assets/welcome.html
        replaces: fused-studio/welcome
        permissions: [state.connection]
```

| Field | Purpose |
| --- | --- |
| `studio.resources: []` | This pack changes Studio without installing files into an agent project. |
| `studio.ui.assets` | Snapshots the generated HTML, including its CSS and connection-state script. |
| `slot: welcome` | Mounts in the default shell's welcome container. |
| `mode: frame` | Isolates the section's DOM, CSS, and JavaScript. |
| `replaces` | Explicitly removes the bundled welcome contribution from the resolved interface. |
| `permissions` | Requests connection readiness only. It grants no Studio commands or project file access. |

Frame contributions embed CSS and JavaScript in their HTML and require no `--trust-ui-pack` flag. Frame policy blocks external stylesheets, scripts, fonts, and network requests, including relative asset links.

## Configure the Tailwind build

The example uses `tailwindcss` and `@tailwindcss/cli` version `4.3.3` with the [Tailwind CLI](https://tailwindcss.com/docs/installation/tailwind-cli). The source list limits class detection to the panel template.

```css src/input.css
@import "tailwindcss" source(none);
@source "./welcome.html";
```

Keep complete class names in the template for Tailwind's [source detection](https://tailwindcss.com/docs/detecting-classes-in-source-files).

`src/welcome.html` contains utility classes such as `bg-slate-950`, `rounded-2xl`, and `sm:grid-cols-2`, plus one insertion marker in its head:

```html
<style>/* STUDIO_TAILWIND_CSS */</style>
```

`build.mjs` runs the installed Tailwind CLI with `--minify`, inserts the compiled CSS at that marker, and writes `assets/welcome.html`. It preserves the CSS license comment and removes its temporary build directory. `npm run check` recompiles and fails if the committed HTML differs from the current inputs.

Tailwind's base reset is safe inside this frame because it cannot reach Studio's parent document. Theme tokens from the parent also do not automatically cross this boundary; this example declares its own slate and cyan palette.

## Package the panel

Distribute `pack.yaml` and the built `assets/welcome.html`. Include the source template and build files when sharing an editable pack. See [packaging](/harnest/build/project-packs/cli#build-the-branded-command).

## Change another section

For an additional workspace tab, use `slot: workspace.tabs` and remove `replaces`. For an additional inspector section, use `slot: inspector.sections`. To replace a view supplied by another pack, name its qualified contribution ID in `replaces` and load that pack too.

The default pack exposes shell, welcome, appearance, and deployment contributions. Its sidebar, editor, and assistant are internal parts of the shell, not individually replaceable contributions. Swapping those independently requires first exposing a stable slot in the shell or replacing the shell itself.

If the section needs to create projects or execute Studio commands, use a [trusted module](/harnest/studio/mods#write-a-trusted-module). Its CSS shares Studio's page unless you add an isolation boundary. Avoid including an unscoped Tailwind reset in `studio.ui.styles`; prefixing utilities alone does not isolate the reset.

After editing the example, rebuild and restart Studio. Pack assets are immutable snapshots taken at launch, so refreshing the browser alone does not load changed publisher files. Use `?safe-ui=1` to compare the bundled welcome without removing your pack, or launch Harnest directly without `--pack` to exclude external packs entirely.
