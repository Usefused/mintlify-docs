---
title: "Studio in your pack"
description: "Bundle company components, templates, skills, and service connections into a local Harnest Studio distribution."
---

A Harnest pack can combine project hooks with a `studio:` section for a shared component catalog, builder defaults, and UI. Agents and editing sessions remain on each teammate’s device. Load the pack folder during development, then build its branded command for distribution.

Packs can also [customize Studio's themes, layouts, and views](/harnest/studio/mods). The default Fused interface is itself a bundled Harnest pack. UI contributions are loaded by Studio and remain separate from resources installed into agent projects.

[Add a Studio section to a pack](/harnest/build/project-packs/cli#include-your-companys-studio) to launch its UI with `acme studio` and use its project hooks with `acme init`.

Studio catalog loading reads only the manifest and referenced files. **Create agent** invokes Harnest with the loaded packs and runs their project hooks in that command; installing a template resource from the catalog uses the separate reviewed resource-installation flow.

## Choose a resource type

| Kind | Contribution |
| --- | --- |
| `component` | Native tools, subagents, workflows, or other source files |
| `extension` | A complete native Harnest Extension directory |
| `template` | A starting agent containing `agent.py` and `config.yaml` |
| `agent-skill` | Agent Skills copied into the agent project |
| `builder-skill` | Markdown guidance supplied to Studio's builder, without copying it into the agent |
| `service` | Internal MCP or Fused connection source using credential references |
| `profile` | A reviewed configuration overlay, optionally accompanied by source files |
| `bundle` | An ordered collection of resources, including resources from other loaded packs |

The component library and AI builder share a catalog. Selecting a resource by ID prepares a diff from its packaged source.

## Author a pack

Create a `pack.yaml` manifest and the text files it references:

```text
company-pack/
├── pack.yaml
├── components/
│   └── ticket_reference.py
└── skills/
    └── builder.md
```

```yaml pack.yaml
apiVersion: harnest.dev/pack/v1
name: acme-support
version: 1.0.0
title: Acme support
requires:
  studio: ">=0.1,<0.2"
  harnest: ">=1.5,<2"
studio:
  resources:
    - id: ticket-reference
      kind: component
      title: Ticket reference
      description: Format an internal support ticket reference.
      files:
        tools/ticket_reference.py: components/ticket_reference.py
    - id: builder-conventions
      kind: builder-skill
      title: Acme builder conventions
      files:
        skills/acme-builder/SKILL.md: skills/builder.md
    - id: team-profile
      kind: profile
      title: Team configuration
      config:
        server:
          agui: true
    - id: support-tools
      kind: bundle
      title: Support tools
      includes:
        - ticket-reference
        - team-profile
```

Each `files` key is a destination inside the agent project. Its value is a path inside the pack. Paths must refer to supported UTF-8 source files; linked files, path traversal, hidden files, and environment directories are excluded. Studio resource installation does not run `pack.py` hooks or substitute template expressions. Project initialization and upgrades can run explicitly selected pack hooks.

```python components/ticket_reference.py
from harnest.agent import tool


@tool
def ticket_reference(ticket_id: str) -> str:
    """Format an internal support ticket reference."""
    return "SUP-" + ticket_id.strip().upper()
```

```markdown skills/builder.md
Prefer Acme support components for internal ticket handling.
Use environment references for credentials.
Review source changes before applying them.
```

Profiles merge their keys into the existing `config.yaml`; the complete resulting diff is reviewed before application. Put a template before its profile in a bundle to compose a new agent with team defaults. Conflicting file contributions are rejected. Template resources must include `agent.py` and `config.yaml`; add dependency and instruction files as needed.

Use `pack-name/resource-id` to reference another loaded pack. Unqualified bundle members refer to resources in the same pack. Unknown references and cycles fail validation.

For extensions, include the manifest, implementation, and supporting files under `extensions/<name>/`. Use the normal [Harnest Extension contract](/harnest/build/extensions/create). Declare agent dependencies in its dependency file and synchronize the environment before running it; Studio does not install arbitrary packages while loading the catalog.

## Configure the Studio builder for your team

One company pack can contain every component, template, and skill alongside the settings for Studio's own builder agent. Add builder defaults under `studio.builder` in `pack.yaml`:

```yaml
studio:
  builder:
    model: openai/company-coding-model
    api_base: https://ai.company.example/v1
    api_key_env: COMPANY_AI_KEY
    ca_bundle: certificates/company-ca.pem
    timeout: 240
    max_tokens: 12000
```

`model` is a LiteLLM provider/model identifier. `api_base` is the model service's base URL, without embedded credentials or query parameters. `api_key_env` names an environment variable resolved on the employee's device; its value is never included in the company wheel. Standard provider credential variables still work when no builder-specific key is supplied.

`ca_bundle` points to a PEM certificate bundle relative to the pack directory. Put your organization's trusted CA certificates there. Studio validates and snapshots the file, includes it in the company wheel, and passes its trust configuration to the builder's provider client while retaining certificate and hostname verification. Linked files, paths outside the pack, invalid certificates, and private keys are rejected. A CA bundle configures server trust; it does not configure an mTLS client certificate or private key.

`timeout` is the per-call limit in seconds (1–1800); `max_tokens` is the output token budget (1–131072). Omitted fields retain Studio's defaults: 120 seconds and 12000 tokens. A settings-only pack can omit `studio.resources`.

These defaults apply automatically when launching with `--pack` or the packaged company launcher. They configure the **Studio builder**, independently of the model settings inside the agents it creates. Credentials must be available through the device's launch environment.

Local settings take precedence:

| Pack field | Local override |
| --- | --- |
| `model` | `HARNEST_BUILDER_MODEL` |
| `api_base` | `HARNEST_BUILDER_API_BASE` |
| `api_key_env` lookup | `HARNEST_BUILDER_API_KEY` (the actual key) |
| `ca_bundle` | `HARNEST_BUILDER_CA_BUNDLE` (a local PEM path) |
| `timeout` | `HARNEST_BUILDER_TIMEOUT_SECONDS` |
| `max_tokens` | `HARNEST_BUILDER_MAX_TOKENS` |

Model and budget choices saved in the Studio UI override launch defaults for subsequent requests. Restart Studio after changing its launch environment or pack contents. A local CA override replaces the bundled trust file; include every required CA in the selected bundle.

Multiple packs overlay their declared fields in `--pack` order. Pack names must be unique.

## Validate and try locally

```bash
harnest pack validate ./company-pack
harnest studio --workspace ./agents --pack ./company-pack
```

Repeat `--pack` to load multiple catalogs. Supply required project-hook options with `--option`, for example `--option team=support`, or use defaults in the pack’s options model. You can also use the standalone `harnest-studio` command from the `harnest-agent-builder` Python package. Both launchers require the Harnest CLI on the device.

In Studio, open **Studio Packs** or choose a company resource in the component library. Templates and bundles containing templates offer **Create agent**. Other installable resources offer a reviewed change to the selected agent. Builder skills are active authoring guidance and do not grant permission to execute commands or expose credentials.

Loading a pack freezes its referenced content for that Studio session. Restart Studio to load publisher changes. Catalog discovery and preview do not execute contribution code; installed Python components execute through the agent's normal runtime when used.

## Package for your team

Set `command: acme-studio` in the example's `pack.yaml`, then build and install it:

```bash
harnest pack build ./company-pack --output ./dist
python -m pip install ./dist/harnest_pack_acme_support-1.0.0-py3-none-any.whl
acme-studio studio --workspace ./agents
```

The `harnest-pack-acme-support` wheel contains the pack folder and a branded launcher. It excludes caches, build output, virtual environments, `.env` files, and `node_modules/`. The launcher attaches the installed pack to `init`, `upgrade`, and `studio`; other commands forward to Harnest.

<Note>
Pack wheels declare no Python dependencies and do not embed Python, Harnest, or Studio. Install Harnest separately. Its `studio` command prepares the bundled Studio runtime on first launch; standalone Python integrations need Studio installed in their environment. Manifest `requires` ranges are checked before loading; they do not install software. For offline installation, supply the required packages in a wheelhouse for the target operating system and Python version.
</Note>

Keep credentials out of packs. Internal service definitions should reference values such as `${COMPANY_MCP_URL}` and `${COMPANY_MCP_TOKEN}`, supplied through the employee's trusted launch environment or connection system.

## Update agents without replacing team edits

Installing a resource records its pack version, content digest, and installed file hashes under `resources` in `harnest-packs.lock`. Publish a new pack version to make updates available for review in Studio. See [versions and ownership](/harnest/build/project-packs/plans-and-recovery#track-versions-and-ownership).

Studio rechecks source revisions when applying. Conflicting local edits block the update. Files omitted from an updated resource remain in the agent. Commit the installation receipt alongside the source.

Enforce organization policy in your services and CI. Pack settings apply to the local authoring environment; trusted UI modules use the [Studio UI contract](/harnest/studio/mods).
