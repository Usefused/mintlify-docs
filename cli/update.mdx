`fused-cli update` rebuilds an existing SDK or MCP server, using the configuration from its most recent (or a specified) version as the baseline. Use it when the underlying API has changed, when you want to adjust the endpoint selection you made in the Cart UI, or when you need to switch the output type or deployment target without starting over from scratch.

## Usage

```bash
fused-cli update <name>[@version] [flags]
```

## Version syntax

By default, `fused-cli update` targets the latest version of the named artifact. To rebuild from a specific version, append `@<version>` to the name:

```bash
fused-cli update support-agent-mcp          # uses the latest version
fused-cli update support-agent-mcp@1.0.0   # uses version 1.0.0 as the baseline
```

## Flags

<ParamField path="--type, -t" type="string">
  Override the target type for the rebuilt artifact. Accepted values: `sdk`, `mcp`. Defaults to the type recorded in the baseline version.
</ParamField>

<ParamField path="--language, -l" type="string">
  Override the language for the rebuilt artifact. Accepted values: `typescript`, `python`. Defaults to the language recorded in the baseline version.
</ParamField>

<ParamField path="--deploy" type="boolean" default="false">
  Deploy the rebuilt MCP server to Fused-Run after building. Requires the artifact to be of type `mcp` and language `typescript`.
</ParamField>

<ParamField path="--api-key" type="string">
  Your Fused API key. Overrides the `FUSED_API_KEY` environment variable for this invocation.
</ParamField>

## How update works

<Steps>
  <Step title="Load the baseline">
    Fused fetches the configuration of the specified version — the original description, the endpoint set you confirmed in the Cart UI, the type, and the language.
  </Step>
  <Step title="Open the Cart UI">
    The interactive Cart UI opens pre-populated with the endpoints from the baseline, so you can review the current selection and make any additions or removals before the rebuild starts.
  </Step>
  <Step title="Rebuild and deliver">
    Fused regenerates the artifact with any changes you made. You receive a new `.zip` archive or, if you passed `--deploy`, a fresh Fused-Run deployment.
  </Step>
</Steps>

## Examples

<CodeGroup>
  ```bash Update to the latest version
  fused-cli update support-agent-mcp
  ```

  ```bash Rebuild a specific version
  fused-cli update support-agent-mcp@1.0.0
  ```

  ```bash Override type and language
  fused-cli update support-agent-mcp -t mcp -l python
  ```
</CodeGroup>

## When to use `update` vs `create`

Use **`update`** when you already have a Fused artifact and want to:
- Refresh it after an upstream API has changed
- Adjust the endpoint selection without rewriting your description
- Switch the artifact to a different type or language
- Redeploy a TypeScript MCP server to Fused-Run

Use **`create`** when you are starting a brand-new integration that has no prior version in Fused.

<Note>
  `update` does not change the name of the artifact. If you need a new name, use `create` instead.
</Note>
