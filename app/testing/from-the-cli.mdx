---
title: "Test from the CLI"
description: "Prove credentials, scope, and routing from a terminal or a CI job — without writing application code."
---

Use `app invoke` to test an exact SDK, REST, or Unified App version with your execution token. Call MCP apps through an MCP client; the CLI manages their deployment, inspection, and tokens.

<Warning>
  Your application should never shell out to this. It is a debug and CI surface with its own limits — [run an operation](/app/run-an-operation) is how your code calls the same path.
</Warning>

## Call something

```text
fused-cli app invoke <app-name@version-or-version-id> <operation>
```

The version reference is required and exact — `app invoke` never picks a version for you, which is the property that makes it useful in CI.

```bash
export FUSED_APP_TOKEN='...'

fused-cli app invoke support-sdk@1.1.0 issueUpdate \
  --params '{"id":"ISS-42","state":"done"}'
```

Operations require a JSON object for `--params`. Any JSON option also accepts `@file`, or `-` for stdin, which keeps large payloads and anything sensitive out of your shell history.

If the selected bucket is still missing a required static credential, `app invoke` stops before contacting the provider and prints the exact `fused-cli connect` command for that service, bucket, authentication type, and scheme. Store the value securely, then repeat the same invocation.

```bash
fused-cli app invoke support-sdk@1.1.0 issueUpdate --params @./payload.json
```

## In a pipeline

Keep the token out of the environment where you can, and gate on the structured output rather than the exit code alone.

```bash
printf '%s' "$CI_SDK_TOKEN" | fused-cli app invoke support-sdk@1.1.0 healthPing \
  --token-stdin \
  --idempotency-key "release-${GIT_SHA}" \
  --no-input \
  --json
```

`--json` prints the endpoint, physical results, status, and timing, so a job can assert on what actually ran. A stable `--idempotency-key` keeps a retried job from counting as a second logical request.

## Flags

| Flag | What it does | Example |
|---|---|---|
| `--params` | One duplicate-free JSON object, `@file`, or `-` | `fused-cli app invoke support-sdk@1.1.0 issueUpdate --params '{"id":"ISS-42"}'` |
| `--token-env` | Reads the token from another variable | `fused-cli app invoke support-sdk@1.1.0 op --token-env CI_SDK_TOKEN` |
| `--token-stdin` | Reads the token from stdin, avoiding the environment | `printf '%s' "$TOKEN" \| fused-cli app invoke support-sdk@1.1.0 op --token-stdin` |
| `--environment` | Provider environment selector, sugar for `--selector` | `fused-cli app invoke support-sdk@1.1.0 op --environment sandbox` |
| `--selector` | Strict selector JSON or `@file` | `fused-cli app invoke support-sdk@1.1.0 op --selector '{"environment":"sandbox"}'` |
| `--idempotency-key` | A stable logical-request key; generated when omitted | `fused-cli app invoke support-sdk@1.1.0 op --idempotency-key run-2026-08-19-a` |
| `--json` | Prints endpoint, physical results, status, and timing | `fused-cli app invoke support-sdk@1.1.0 op --no-input --json` |

The token comes from `FUSED_APP_TOKEN` unless you redirect it. Management credentials and provider credentials are never substituted for it.

## Limits worth knowing

This is a debug surface, not a production transport. It accepts one buffered JSON provider document up to 1 MiB. Generated SDKs keep their broader gRPC transports, so a payload that fails here may be perfectly fine from your application.

It produces one logical Fused execution and does not retry locally or follow redirects itself — Fused owns retries, pagination, and continuation.
