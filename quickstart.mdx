Fused lets you go from an API description to a fully typed, published SDK in a single CLI command. This guide walks you through installing `fused-cli`, authenticating with your API key, and generating a real multi-service SDK that combines Jira, GitHub, and Slack into one business-capability package — the kind of integration that would normally take days to wire up by hand.

## Prerequisites

Before you begin, make sure you have the following:

- **A Fused account** — [request access at usefused.com](https://usefused.com/#access) if you don't have one yet.
- **Your `FUSED_API_KEY`** — found in the **API Keys** section of your Fused dashboard.
- **Node.js 18+** — required to install and run the generated SDK packages.

## Step 1 — Install fused-cli

Choose the installation method that matches your environment:

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    curl -sSL https://raw.githubusercontent.com/Usefused/cli/main/install.sh | bash
    ```
  </Tab>
  <Tab title="Windows (PowerShell)">
    ```powershell
    irm https://raw.githubusercontent.com/Usefused/cli/main/install.ps1 | iex
    ```
  </Tab>
  <Tab title="Go install">
    ```bash
    go install github.com/Usefused/cli@latest
    ```
  </Tab>
</Tabs>

Verify the installation succeeded:

```bash
fused-cli --version
```

## Step 2 — Set your API key

Export your key as an environment variable so every `fused-cli` command can authenticate automatically:

```bash
export FUSED_API_KEY="sk_test_..."
```

<Tip>
  Add this line to your shell profile (`~/.zshrc`, `~/.bashrc`, or equivalent) so you don't have to re-export it in every new terminal session. You can also pass the key explicitly on any command using the `--api-key` flag.
</Tip>

## Step 3 — Generate your first SDK

Run `fused-cli create` with a name, version, and a plain-English description of what you want the SDK to do. Fused resolves the right services, scopes the relevant endpoints, and publishes a typed npm package.

```bash
fused-cli create \
  --name onboarding-sdk \
  --version 1.0.0 \
  --type sdk \
  --language typescript \
  -d "When a new employee joins, use Jira to create an onboarding ticket, use GitHub to provision repository access, and use Slack to send a welcome message"
```

The key flags for `fused-cli create` are:

| Flag | Default | Description |
|------|---------|-------------|
| `--name` | — | Name for the generated artefact (required) |
| `--version` | — | Semantic version string, e.g. `1.0.0` |
| `-d` | — | Plain-English description of the desired workflow (required) |
| `--type` | `sdk` | Artefact type: `sdk` or `mcp` |
| `--language` | `typescript` | Output language: `typescript` or `python` |
| `--deploy` | — | Deploy a TypeScript MCP server directly to Fused-Run |
| `-y` | — | Skip the interactive Cart UI and proceed automatically |

<Tip>
  Before the SDK is generated, Fused opens the **Cart UI** in your browser — an interactive checklist of every endpoint that will be included. Review and deselect any operations you don't need before confirming. This keeps your SDK lean and your bundle size small. Pass `-y` to skip the Cart UI in automated or CI workflows.
</Tip>

Fused will:

1. Resolve the Jira, GitHub, and Slack services from its registry.
2. Scope each service to only the endpoints your description requires.
3. Bundle them into a single `@acme/onboarding-sdk` npm package.
4. Publish the package and print the install command.

## Step 4 — Install and use the generated SDK

Install the published package into your project:

```bash
npm install @acme/onboarding-sdk
```

Then import and use the typed client in your application:

```typescript
import { FusedSDK as OnboardingSDK } from "@acme/onboarding-sdk";

const sdk = new OnboardingSDK({
  jira: { token: "jira_..." },
  github: { token: "ghp_..." },
  slack: { token: "xoxb_..." }
});

// Create an onboarding ticket in Jira
const ticket = await sdk.jira.issues.create({
  project: "ONBOARD",
  summary: "Onboard new engineer: Jane Doe",
  issueType: "Task",
  assignee: "jane.doe"
});

// Provision repository access on GitHub
await sdk.github.repos.addCollaborator({
  owner: "acme-corp",
  repo: "platform",
  username: "jane-doe-gh",
  permission: "push"
});

// Send a welcome message in Slack
await sdk.slack.chat.postMessage({
  channel: "#engineering",
  text: `👋 Welcome Jane! ${ticket.data.key} created and repo access granted.`
});
```

Every method is fully typed — your editor will autocomplete parameters, flag mismatched types, and surface the response shape inline, with no manual type definitions required.

<Note>
  Each service within the bundle authenticates independently. You can supply tokens at initialisation time (as above) or set them as environment variables — see the [SDK guides](/guides/sdk-overview) for all supported auth patterns.
</Note>

## Other CLI commands

Once you have an artefact, you can iterate on it or retrieve it later using two additional commands:

**Update an existing artefact** — re-run generation using the same name as a baseline, optionally changing type, language, or adding `--deploy`:

```bash
# Update the most recent version
fused-cli update onboarding-sdk

# Update a specific version
fused-cli update onboarding-sdk@1.0.0 --type mcp --deploy
```

**Download a previously built artefact** — retrieve the source `.zip` without re-generating:

```bash
# Download the latest build
fused-cli download onboarding-sdk

# Download a specific version to a local directory
fused-cli download onboarding-sdk@1.0.0 --output ./my-sdk
```
